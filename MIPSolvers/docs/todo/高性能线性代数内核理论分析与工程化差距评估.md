## 0. 结论先行

**对"当前方案仍是研究级、离工程实践尚远"这一判断的裁定：在一半维度上成立，在另一半维度上恰好相反。**

- **算法选型层面已达到甚至超过工程实践水准。** 三套生产因子分解族（HFactor/Markowitz-FT、CHOLMOD supernodal、MUMPS 多波前 LBLᵀ）与综述表 2 中的主流谱系逐一对应；对偶单纯形的 Goldfarb–Reid DSE 递推、Harris 两遍比值检验、Forrest–Tomlin 更新、超稀疏 FTRAN/BTRAN，IPM 的 Mehrotra + Gondzio 多中心校正、analyze-once/factorize-many、Ruiz 均衡，均是各自领域的教科书级正确选择。逐 solve 的后向误差验收（256ε 合同，`factor.cpp:361-377`）、三通道惯性证书（`kkt_system.cpp:566-656`）、结果密度 EWMA 反馈（`hfactor_backend.cpp:52-58`）这三项，**HiGHS 与多数商业求解器并不做**——这是超出工程实践的部分。
- **真正的研究级/工程级差距不在算法，而在综述第 2.2 节命名的四条演进线索上：本内核在"排序质量、并行、批处理接口、混合精度"四轴上分别处于缺席、串行、半成品、零的状态。** 叠加三项综述未直接覆盖但决定可部署性的工程轴——平台可移植性（性能与开发机 Apple Silicon 深度纠缠）、并发架构（MUMPS 全局互斥）、基准广度（仅 NETLIB-24，无电力矩阵）——构成"离工程实践尚远"感受的全部实质来源。
- **理论上最重要的单点认识：本内核服务的矩阵类别（LP 基矩阵、电网型 KKT）是综述 §1.1 所述"极端稀疏 + 小世界"矩阵，其求解在 roofline 意义下是带宽受限的（算术强度 ≈ 0.17 flop/byte，见 §2.2）。** 这一事实同时解释了（i）为什么 native dual simplex 的 §13.3 "bytes 同降" gate 是理论上正确的度量、（ii）为什么对偶单纯形残余的 12.5% 差距已抵近该设计点的硬件极限（综述 §2.4："CPU 直接法已高度成熟、逼近硬件极限"）、（iii）为什么下一个数量级的收益只能来自四条演进线索（少做工作：排序/复用；换算力结构：并行/精度/GPU），而不是继续压缩 per-pivot 常数。

后文 §8 按"理论收益 × 工程风险"给出排序后的路线，每项附收益模型与验收 gate。

## 1. 现状盘点：src/engine 的线性代数栈全景

代码勘察确认存在**四个相互独立的因子分解族**，按消费者静态绑定，无统一运行时调度：

| 族 | 算法 | 排序 | 基更新 | 并行 | 精度 | 生产消费者 |
|---|---|---|---|---|---|---|
| **HFactorBackend**（vendored HiGHS HFactor, git `dcc25308d` v1.14.0） | Markowitz 阈值主元 LU + Gilbert–Peierls 超稀疏三角解 | 动态 Markowitz（局部） | Forrest–Tomlin（PF/MPF/APF 被硬禁用，`HFactor.cpp:1599` 等处 assert） | 串行、标量 | FP64 | native dual simplex（`native_dual/factor.hpp:143`）、B&C crash basis |
| **CholmodLDLT** | supernodal BLAS-3 LLᵀ/LDLᵀ（SPD）；simplicial LDLᵀ（拟定 KKT，`cholmod_ldlt.cpp:166-174`） | **仅 AMD 族**（构建时排除 METIS/Partition，`cmake/BuildCHOLMOD.cmake:74`） | 无 | 仅 BLAS 内部线程 | FP64（`CHOLMOD_DOUBLE`，`cholmod_ldlt.cpp:95`） | IPM-LP 法方程、conic KKT |
| **Apple Accelerate Sparse** | 无主元 LDLᵀ / Cholesky + `SparseRefactor` | Apple 内部 | 无 | **多线程**（栈内唯一） | FP64 | IPM-LP（macOS 上优先于 CHOLMOD，`ipm_lp_solver.cpp:578-589`；增广 KKT 在 nn+m≥5000 时启用，`:951`） |
| **SparseLinearSolver 族** | 编译期级联 KLU→UMFPACK→PARDISO→SuperLU→Eigen（`linear_solver.cpp:466-483`）；MumpsSolver 多波前 Bunch–Kaufman LDLᵀ 显式构造 | AMD/COLAMD；MUMPS `ICNTL(7)=7` 自动（PORD 随包，METIS 视构建） | 无 | **MUMPS 被进程级递归互斥串行化**（`linear_solver.cpp:269`） | FP64 | NLE 牛顿、KKT、LCQP、conic |

另有：手写带状 Cholesky 与稠密 `dsyrk`+LDLᵀ 回退（`ipm_lp_solver_internal.hpp:242-289`、`ipm_lp_solver.cpp:1151`）；`SparseLUFactor`（UMFPACK 抽取 + 自研 FT）**已无任何生产接线**，属遗留代码，不得将单纯形性能归因于它。

**消费者→后端映射**：对偶单纯形/B&C → HFactor；IPM-LP 按带宽/密度四路分派（带状/稠密/稀疏 NE/增广 KKT，`ipm_lp_solver.cpp:363-383,494-500`）→ Accelerate/CHOLMOD/Eigen；NLP-KKT → MUMPS（可选）或通用 LU；conic → CHOLMOD+MUMPS 升级链（`conic_ipm_solver.cpp:629-664`）。

**全栈横切事实（grep 级核实）**：无 GPU 路径（无 cuDSS/cuSOLVER/CUDA），无混合精度（全 FP64），无 x86 SIMD（仅 ARM NEON：BFRT 预过滤 `pricing.cpp:403-481`、IPM 迭代更新 `ipm_lp_solver_internal.hpp:124-234`），因子分解全部串行（OpenMP 仅用于 IPM 的 SpMV 外层循环，阈值 4096，`ipm_lp_solver_internal.hpp:52-61`）。

## 2. 理论框架：这类矩阵上的求解成本解剖

### 2.1 成本三分与复用结构

直接法成本 = 符号分析 + 数值分解 + 三角回代。综述 §2.2/§2.3 的核心工程判断是：三者的比例结构决定优化方向，且"符号一次化 + 数值分解/回代高频化"是在线应用的标准形态。本内核在**单次求解内部**已完全内化这一结构：

- `kkt_system.cpp:206-242`：模式未变则跳过 `analyze_pattern`，并以 `symbolic_analyses` / `numeric_factorizations` / `linear_solves` 三计数器显式度量该比例——这正是综述所述成本结构的第一手仪表化。
- B&C 节点 LP 缓存（`ipm_lp_solver_cached.cpp`）：符号分解、scatter 映射、Ruiz 缩放、最小二乘对偶初值全部按"模式不变、仅界变"摊销，逐节点只做数值分解——与综述 §2.2 线索三"同一稀疏模式、数百至数千个不同数值矩阵"的批处理洞见结构同构。
- 对偶单纯形以 FT 更新把"重分解"摊薄为 rank-1 修正，重分解间隔理论最优点 T\*=√(2R/u) 已实现为诊断模型（`solver.cpp:406-415`），且经 DR-4 实测判定现行策略不劣（git `4eb5480`）——这是"测过并拒绝"而非"没想到"，应记为工程证据文化的加分项。

### 2.2 Roofline：为什么这类内核是带宽受限的，以及它的三个推论

稀疏三角回代对每个因子非零元执行 2 flop（乘加），读取 ≈12 B（8 B 值 + 4 B 索引）加上解向量流量，算术强度 AI ≈ 0.17 flop/B，远低于现代 CPU 的机器平衡点（5–15 flop/B）。因此：

$$T_{\text{solve}} \approx \frac{\text{bytes}(L,U\ \text{触达部分})}{\text{有效内存带宽}},\qquad T_{\text{factor}}^{\text{simplicial}} \approx \frac{\text{bytes}(\text{kernel 扫描})}{\text{带宽}}.$$

综述 §1.1 指出电网矩阵"每行非零元不足 10 个、结构不规则、缓存复用与向量化困难、计算呈内存受限特征"——LP 基矩阵与 SCUC 松弛的 KKT 完全同类。三个推论：

1. **bytes 是第一性成本度量。** 路线图 §13.3 的"有效 bytes 与动态指令同降"gate 与深度分析用 bytes 归因六项结构性税，是该 roofline 事实的正确方法论表达。这不是本仓库的偶然发明，而是内存受限内核的标准分析姿势。
2. **逃逸带宽墙只有两条路**：把标量非零元聚成稠密块换 BLAS-3（supernodal/多波前，AI 随块尺寸线性升高）——但小世界矩阵天然缺乏大 supernode，收益封顶；或**少搬 bytes**——排序降 fill、复用因子、砍冗余遍历、降精度减半流量。综述四条线索里有三条（排序、复用/批处理、混合精度）本质上都是"少搬 bytes"。
3. **per-pivot 微优化存在硬地板。** 深度分析 §9 已把 native dual 残余差距归因为"认证算术的常数因子机器"，且实证了逐项去除收益趋零。roofline 视角给出同一结论的硬件表述：当每 pivot 的有效 bytes 已逼近必要下界，剩余墙钟差即设计点差（认证核 vs 启发式核），继续压缩的边际收益 → 0。

### 2.3 Fill-in 理论：排序是大规模场景下唯一的多项式级杠杆

George 定理：√n×√n 网格图在嵌套剖分（ND）下 fill Θ(n log n)、分解 flops Θ(n^{3/2})；最小度类启发式（AMD）无此保证。电网/管网类近平面小世界图对排序质量的敏感性正是综述 §2.2 线索一的内容——"同为 IBM 电网基准矩阵，不同求解器因子非零元可相差数倍"。关键的复合效应：**nnz(L) 同时决定分解与其后每一次回代的 bytes**，在 IPM 里乘以迭代数（数十次分解 + 每次 4–8 回代），在"符号一次、数值千次"的场景里乘以场景数。

现状对照：CHOLMOD 构建时显式排除 Partition/METIS 模块（`BuildCHOLMOD.cmake:74`），IPM 法方程只有 AMD 族排序；Eigen 回退同为 AMD（`ipm_lp_solver.cpp:408`）。在 NETLIB 尺度（m~10³）AMD 与 ND 差距通常可忽略；在 SCUC/电网尺度（m~10⁵⁺）该差距按上述理论呈多项式增长。**这是当前栈唯一"随规模恶化且无缓解机制"的结构性缺口**。（MUMPS 路径 `ICNTL(7)=7` 自动排序含 PORD，属例外，但 MUMPS 非默认。）

### 2.4 病态与正则化：与综述 §2.4/§5.5 的对照

综述的核心论断——"电力问题的求解器瓶颈不在分解本身，而在病态+不定+高频重分解的组合"——本内核的应对属于文献前沿而非落后：IP-PMM 式随 μ 联动的原/对偶正则化（`ipm_lp_solver.cpp:1493`）、Wächter–Biegler δ_W 阶梯 + 三通道惯性证书（约减空间特征值证书 / MUMPS `INFOG(12)` / Eigen LDLᵀ 符号，`kkt_system.cpp:373-410,566-656,667-727`）、以及**门控迭代精化以消除正则化偏置**（相对 KKT 残差 >1% 才触发、验证无效即回退，`ipm_lp_solver.cpp:1357-1404`）。SCUC 稠密耦合行导致 N=AΘAᵀ 近稠密时逃逸到拟定增广系统（`:383` 注释给出 39-bus 实测 1.7×、6-bus 10×）——这与综述 §5.5 "改变问题结构而非硬搬算法"（HyKKT/LiftedKKT 凝缩路线）的方法论一致，只是方向相反（凝缩→增广 vs 不定→凝缩），同样是按矩阵结构择形。

## 3. 综述四条演进线索 × 本内核：逐条定量对照

### 3.1 线索一（排序）：缺席，且是规模可扩展性的第一瓶颈

见 §2.3。补充定量估计：设 AMD 相对 ND 在目标规模的 fill 膨胀率为 φ（电网类矩阵文献区间 1.5–5×），则 IPM 单次求解墙钟近似按 φ 线性放大（分解与回代均 bytes ∝ nnz(L)，supernodal flops 项按 φ^{3/2} 更陡）。**修复成本极低**：CHOLMOD 的 Partition 模块 + vendored METIS 是纯构建项，运行时可对首个符号分析并行试排（AMD vs ND，取 nnz(L) 小者），符号分析在 analyze-once 模式下是一次性成本。

### 3.2 线索二（并行）：因子分解全串行，且并发架构存在硬锁

- 单个因子分解内部：HFactor 串行（与 HiGHS 默认一致，单纯形场景合理——基矩阵消去树浅、supernode 小，树级并行收益有限）；CHOLMOD supernodal 仅靠 BLAS 线程；Accelerate 多线程（Apple 独占）。
- **真正的理论错位在并行轴的选取**：对 MIP/多场景工作负载，正确的并行粒度不是"单个分解内部"（受消去树高度限制，小世界矩阵 speedup 封顶 2–4×），而是**跨节点 LP / 跨场景**（尴尬并行，综述 §5.5 ExaSGD 两阶段分解的粒度选择同理）。当前架构对此有两个硬障碍：MUMPS 进程级互斥（`linear_solver.cpp:269`，Fortran 模块态非线程安全的保守处理）使并行 B&C 的 NLP/KKT 求解互相串行化；`thread_local` scratch 设计（`solver.cpp:486,506` 等）保证了线程安全但只是"可并存"而非"可并行协作"。
- 已有的正确内核级并行：BFRT 大扫描的 worker 数不变式合并（≥8192 候选才启用、按 PRICE 原序归并保证逐位确定，`pricing.cpp:1004-1111`）——这是把"并行不得改变数值路径"合同做对了的范例，工程实践中反而少见。

### 3.3 线索三（批处理/模式复用）：单流内做满，跨流接口缺失

已对齐综述的部分（见 §2.1）：analyze-once/factorize-many、B&C 节点缓存、对偶单纯形 warm state（S5）、`AccelSparseCache` 跨 `solve_lp` 复用符号分解。**缺失的是三种跨流批形态**：

1. **多 RHS 块回代**：Mehrotra 预测/校正/Gondzio 校正/迭代精化对同一因子逐一 backsolve（每 IPM 迭代 4–8 次 O(nnz(L)) 遍历）。块化为多列 RHS 可把 BLAS-2 型遍历升为 BLAS-3 型（supernodal 路径），或至少把因子 bytes 的重复流式读取摊薄 k 倍——带宽受限内核里这是直接的 bytes 削减。注意依赖链约束：predictor→corrector 有数据依赖，可块化的是 Gondzio 多校正内部与精化残差组。
2. **跨场景批分解接口**：综述 §2.2/§2.3 指出 SuperLU_DIST 9.0 与 cuDSS 的 batched 接口正是为"N-1 预想事故 / 蒙特卡洛"负载而生。SCUC 的多时段/多场景松弛属同类负载，当前 API 无表达能力（每 LP 独立走全流程）。
3. **单纯形侧的 solve 批**：per-pivot 1 BTRAN + 2 FTRAN（+flip FTRAN）已通过 capture 复用消除了重复 scatter（`ftran_indexed_at_captured_pattern`，`hfactor_backend.cpp:885-948`），单流内已无批化空间；跨流（并行 strong branching 的多基）是唯一剩余批轴。

### 3.4 线索四（混合精度）：零实现；理论上 IPM 前中期可用、单纯形不可用

理论边界（Higham/Carson–Higham）：LU/Cholesky 基精化的 Richardson-IR 收敛条件 ≈ κ(A)·u_f < 1，FP32（u_f=2⁻²⁴）要求 κ ≲ 10⁷；GMRES-IR 把包络推到 κ·u ≈ 1（工作精度 u=2⁻⁵³）。IPM 的 κ(AΘAᵀ) 随 μ→0 以至多 Θ(μ⁻²) 增长：**μ ≳ 10⁻³ 的前中期迭代满足 FP32 分解条件，末期必须 FP64**——与综述 §4.1 的谨慎结论（"OPF KKT 末期 κ 可达 10¹⁶，GPU IPM 实践仍以 FP64 为主"）完全一致。收益上界由 roofline 给出：FP32 使因子 bytes 减半 → 分解+回代 ≤2×，supernodal BLAS-3 部分再享 2× flops——**上界 2×，不是数量级**，且需按 κ 估计的相位切换机制与系统性误差验证（综述 §4.1 明言此项研究在电力场景尚缺位）。

**对偶单纯形明确不适用**：认证算术（Strategy M 支配界、逐 solve 后向误差合同）与逐位路径合同（bit-identical pivot path）在语义上排斥低精度分解；深度分析 §9.8 已裁定"降精度成启发式核是产品定位抉择而非优化"。混合精度的正确落点是 IPM/KKT，且应以 GMRES-IR 替换现有固定 2 步 Richardson 精化（`kkt_system.cpp:266-277`）作为前置——后者即便在纯 FP64 下也是收敛包络更窄的选择。

## 4. 迭代法与预条件：空白，但多数场景理应空白

栈内无任何 Krylov 方法（仅 Richardson 型精化循环）。按综述 §3.4 的适用边界裁定，这一空白**大部分是正确的**：B&C 节点 LP 流的"预条件复用"正确形态是对偶单纯形热启动（已有，S5）——warm basis 之于单纯形恰如冻结 ILU 之于 Newton–Krylov，是同一"一次分解、多次复用"思想在不同解法族的投影；固定模式高频重解场景直接法不可撼动（综述 §3.4-iv）。真正值得补的两个窄口：（i）**GMRES-IR** 作为 KKT/精化的鲁棒层（见 §3.4，兼作混合精度使能件）；（ii）若 SCUC 规模增长到 NE 因子内存不可承受（当前已有 100M scatter 上限保护，`ipm_lp_solver_cached.cpp:163-168`），matrix-free CG + 冻结预条件是综述 §3.4-i 的既证路线。子空间回收（ReNK 类）对 B&C 的类比物是跨节点对偶信息复用，仓库已在 reduced-cost learning 方向上有等价物，不构成缺口。

## 5. 各内核 vs SOTA 基线：定量评估

### 5.1 native dual simplex vs HiGHS：差距已收敛到设计点差

现状 gate 0.875×（24-case NETLIB，72/72 accurate），pivot 数已全域优于 HiGHS。深度分析把 per-pivot 残差解剖为六项结构性税并逐项实验：可安全消除者已消除（Strategy M 证书重定位、平铺值流、分区 PRICE、结果密度 EWMA），剩余为认证语义的常数因子。**从综述视角看，这条线已经走到了 CPU 直接法"逼近硬件极限"的教科书终点**；残余 12.5% 的对价是 HiGHS 不提供的逐 solve 后向误差合同与证书。剩余的线性代数级杠杆只有一项体量可观：P1 factor-resident workspace（消除 wrapper 的 O(m) 置换 gather 与 packed 导出/重导入，`[DS-EXPORT-SPLIT]` 仪表已就位量化它，`hfactor_backend.hpp:62-66`）。此外注意一个可靠性暗礁：vendored HFactor 主元容差 1e-10 会把轻度病态 SCUC 基误判为秩亏（`hfactor_backend.cpp:305-311` 注释，UMFPACK 可解）——这是研究级"env 可调诊断"与工程级"自适应容差回退"的典型差别。

### 5.2 IPM-LP vs HiGHS-IPM/PCx 谱系：架构同构，输在排序与平台

架构逐项对齐（NE 缺省 + 增广逃逸 + Mehrotra + Gondzio 门控 + Ruiz + 正则化-精化闭环）。Gondzio 校正的经济学实现得正确：每个校正 = 1 次 backsolve（零原始 RHS，`ipm_lp_solver.cpp:1760`），只在步长节流域（min(α_p,α_d)<0.9）启用并按边界步增益验收/回退（`:1734-1791`）——这正是 Colombo–Gondzio 的自适应形式；且随规模增大 C_solve/C_factor → 0，该机制自动增值。差距集中于：无 ND 排序（§3.1）、并行分解仅 Apple 平台可得、无混合精度。**平台悬崖需单独点名**：macOS 上增广 KKT 走 Accelerate 多线程无主元 LDLᵀ（实测 4× 于 CHOLMOD，`:939-957` 注释），Linux 构建则静默降级为串行 simplicial CHOLMOD——同一二进制语义下平台间性能差可达 4–10×，这是"研究原型跑在开发机上"与"工程产品跑在部署机上"最锋利的一条分界线。

### 5.3 NLP-KKT vs Ipopt+MA57：数值机器超配，部署形态欠配

惯性修正的三通道证书交叉验证超出 Ipopt 实践（Ipopt 信任 MA57 惯性单通道）；MUMPS 集成做了 ABI 卫生（拒绝借用 Homebrew 私有库）、null-pivot 检测、逐解 1e-9 残差认证。欠配项：MUMPS 非默认（默认级联落到 KLU 类非对称 LU——对对称不定 KKT 付 ~2× flops 且无惯性，靠外层证书补偿）；全局互斥（§3.2）；增广牛顿路径无形式化惯性证书（`ipm_solver.cpp:734-736` 自注）。综述 §2.4 的评测结论（"OPF KKT 串行 MA27/MA57 即最优，并行反而拖累"）说明该规模域串行 MUMPS 已够格——瓶颈是互斥对**跨问题并发**的封锁，不是单解速度。

### 5.4 Conic/chordal：研究广度资产

NT 缩放全锥系 + 弦分解（贪心最小度消去、clique 提取、PSD 补全，`chordal_decomposition.cpp:38-159,161-227`）属研究前沿功能，多数开源求解器不具备。工程化欠账与 5.2/5.3 同源（后端升级链已有，`conic_ipm_solver.cpp:629-664`），不再展开。

## 6. 研究级 vs 工程级：系统差距矩阵

| 维度 | 现状 | 工程实践基线 | 裁定 |
|---|---|---|---|
| 算法选型 | 四族后端均为 SOTA 正确谱系 | 同 | **达标** |
| 数值鲁棒性/可审计性 | 逐 solve 后向误差合同、三通道惯性、终局审计 | 通常仅容差+启发式 | **超配** |
| 可观测性 | DS-PROFILE 13 桶、REINVERT 模型拟合、密度/EWMA 仪表 | 通常粗粒度计时 | **超配** |
| 单线程性能 | 对偶单纯形 0.875× HiGHS（含认证对价）；IPM 架构同构 | ≈1× 参考实现 | **接近达标** |
| 排序/规模可扩展性 | 无 ND；100M scatter 上限硬保护 | METIS/ND 选项 + 自适应 | **缺口，随规模恶化** |
| 可移植性 | 性能绑定 Apple（Accelerate+NEON）；Linux 静默降级 4–10× | 平台性能矩阵 + CI | **最大工程缺口** |
| 并发架构 | 分解全串行；MUMPS 全局互斥；thread_local 可并存不可协作 | 跨问题尴尬并行 | **缺口** |
| 批处理接口 | 单流内复用完备；跨流/多 RHS 缺失 | batched API（cuDSS/SuperLU 9.0 形态） | **半成品** |
| 精度策略 | 全 FP64；固定 2 步 Richardson 精化 | FP32+IR 选项、GMRES-IR | **缺口（收益上界 2×）** |
| GPU | 无 | 视规模；MA57 域 CPU 仍最优（综述 §2.4） | **当前规模下缺席合理** |
| 基准/验证广度 | NETLIB-24 + SCUC 内部例 | Mittelmann 集 + 电网矩阵（综述 §6.3 挑战三） | **缺口** |
| 生态接口 | 内部 ABI | 无外部诉求则不构成缺口 | 中性 |

**对用户命题的最终裁定**：说"研究级"准确的部分是——性能被单一开发平台、单一基准集、串行执行、FP64 单精度策略所**条件化**，任何一个条件变化（换 Linux、上规模、并发、要吞吐）都会暴露断崖；说"研究级"不准确的部分是——数值可靠性工程（通常是研究代码最弱项）在此反而是最强项。**从研究级到工程级的路径不是重写内核，而是解除这四个条件化。**

## 7. LP 结构特征、算法匹配与执行规则

本节把“观察模型结构”具体化为可计算特征，并规定这些特征只能用于生成和
比较算法候选，不能直接变成案例名、维数或经验阈值路由。决策分成静态图、
数值结构和迭代状态三层；三层分别回答“做什么代数变换”“解哪个 Newton
系统”“失败后保留哪些状态”。

### 7.1 LP 问题的结构特征

设标准化后的约束矩阵为 $A\in\mathbb{R}^{m\times n}$，列图是变量到约束的
二部图，normal 图为 $AA^T$ 的结构图。特征向量不只包含规模：

| 层 | 特征 | 决定的问题 |
|---|---|---|
| 静态局部图 | 空行/空列、固定列、行列度直方图、singleton、degree-2、最大度 | 可逆 presolve 与部分 Schur 候选 |
| 静态全局图 | 连通分量、块角/网络结构、带宽、normal 密度、候选图的 `nnz(L)` 与 symbolic flops | normal/augmented/hybrid 形态及排序 |
| 数值结构 | 行列尺度跨度、活动等式数值秩、主元扰动数、实际 Newton 后向误差 | 正则化、带主元后端与恢复 |
| 迭代状态 | $\mu$、原对偶残差收缩、步长、停滞连续性、失败发生在 factor/solve/update 哪一阶段 | 是否续接轨迹及精化强度 |

关键区分是：度数和边数是候选生成特征，不是 factor 成本。消去一个二度 primal
顶点最多增加一条 dual 边，局部边数严格不增；但新边可能跨越分隔，改变消去
树和 supernode，最终 `nnz(L)`、flops 甚至墙钟仍可上升。因此全局因子图特征
必须覆盖局部图特征的初步判断。

### 7.2 特征与算法如何匹配

匹配遵循“稳定性约束优先，满足后最小化总工作量”原则：

$$
\min\ T_{pre}+T_{sym}+N_{factor}T_{factor}+N_{rhs}T_{solve},
\quad
\text{s.t. Newton 后向误差与原模型审计合同成立}.
$$

| 结构证据 | 候选算法 | 原理与启用条件 |
|---|---|---|
| 固定列、空行列、可逆 singleton | Native presolve/静态凝聚 | 只做可证明可逆的代数等价变换，并保留 postsolve 映射 |
| normal 图窄带 | 带状 Cholesky | $O(mb^2)$ 在窄带域优于通用稀疏排序 |
| normal 图完全稠密 | 稠密 BLAS 或 augmented | 完全图的 `nnz(L)`/flops 可闭式计算，无需重复 symbolic |
| normal 的 `nnz(L)`、flops 均低 | SPD normal + LLT | 维数小、拟定且 factor/solve 可复用 |
| normal fill 失去稀疏经济性，augmented 成本有界 | 拟定 augmented KKT | 避免条件数平方与 normal fill |
| 低度列多、hybrid 图严格更低 | 部分 Schur + augmented LDLT | 精确消元低度列，保留高度列，必须以候选 factor 图复核 |
| factor intensity 高且生产后端实测更优 | PARDISO LLT/LDLT | 利用并行超节点；不能只因“已有 METIS”或规模大而选择 |
| 后向误差超合同或方向非有限 | 带主元恢复/冷重启 | 当前方向不可信，不能续接中间状态 |
| factor 失败或步长舍入停滞，尚未应用坏方向 | 保留 primal、重建 augmented 状态 | 失败点之前的 primal 仍可信，避免重复中心路径 |

Presolve、formulation、backend、recovery 必须分别裁决。Presolve 由代数可逆性
决定；formulation 由消元图与稳定性决定；backend 由同一 factor 图的排序和
数值内核成本决定；recovery 由失败发生的实际阶段决定。把四者压成一个统一
路由会把局部结构、全局 fill 和数值状态混为一谈。

### 7.3 对 presolve 与算法执行的指导

1. **结构扫描只做一次。** 生成固定列、度分布、normal/full-augmented/hybrid
   候选图，符号模式随 barrier 迭代复用。
2. **先排除不等价或不可恢复的变换。** 数值秩 QR 若成本接近一次完整求解，
   只能作为离线诊断，不能进入热路径；`greenbea`/`dfl001` 的 SparseQR 分别约
   1.34 s/50.9 s，已据此拒绝。
3. **候选必须在生产排序与后端上比较。** CHOLMOD symbolic、PARDISO
   `iparm[17]/[18]` 与单位拟定 factor 探针共同用于解释成本；若静态统计与实际
   factor 相反，选择实际总成本更低者，并记录负结果。
4. **运行时只响应数值事件。** `rcond` 是诊断量，方向接受看实际后向误差；
   恢复是否续接看失败前是否应用了坏方向，不看案例身份。
5. **最终结果一律回到原 LP 审计。** 缩放、凝聚、恢复都不能放宽目标和原始
   可行性阈值。

### 7.4 三个长尾案例的独立结论

- **`greenbea`：数值秩/恢复轨迹。** 活动等式结构秩 `2196/2199`，缺失三行
  为三个空行；大量 PARDISO 扰动主元是 barrier KKT 数值事件。normal factor
  失败发生在方向应用前，因此保留 primal 并重建 augmented 状态。NETLIB
  full90 中由 2,636.2 ms/176 次降至 1,621.2 ms/44 次。
- **`dfl001`：增广因子图/排序。** 二度 Schur 候选凝聚 5,274 列，局部边数
  不增，静态 `nnz/work` 也下降；但 PARDISO 实际首因子从约 47.8 ms 升至
  63.8 ms，三次总时间从 2,992.7 ms 退化到 3,654.8 ms。故生产保持 1,370
  个 singleton 精确凝聚，二度模块仅保留为已测试候选。
- **`maros-r7`：SPD 因子图/排序。** normal 为 `491.296M flops / 1.188M
  nnz(L)`；凝聚二度列、保留高度列的 hybrid 为 `494.134M / 1.250M`，符号
  阶段即拒绝。相同 SPD 图上 PARDISO LLT 约 1.25 s，CHOLMOD 约 2.37 s，
  后端继续使用 PARDISO。

正式全量结果为 90/90 accurate，总时间由 11.0762 s 降到 10.1294 s。该轮收益
来自 `greenbea` 的可信状态续接；`dfl001` 和 `maros-r7` 的贡献是阻止错误的
统一路由进入生产。负结果同样是算法资产，因为它缩小了后续优化的合法空间。

## 7.5 从 LP IPM 迁移到 NLP 与 Conic IPM

LP 中“先看消元图、再选公式、最后用数值证书接受方向”的规律可以迁移，
但不能复用 LP 专属阈值。NLP 的两个候选图是 condensed
$H+J_h^T(M/S)J_h$ 与包含 $J_h,-SM^{-1}$ 的 augmented KKT；Conic 的候选
成本必须把 NT scaling、Schur assembly、symbolic、多次 numeric factor 和
affine/corrector solve 分开。稳定性证书分别为 NLP 的 KKT 惯性
`(n,m_eq,0)`/`(n,m_eq+m_ineq,0)`，以及 Conic 在 NT 同坐标 3x3 方程上的
后向误差。

2026-08-06 的工程结果验证了该迁移：NLP Auto 同时比较两个候选的 CHOLMOD
symbolic flops 与 `nnz(L)`；PARDISO LDLT 导出直接惯性，并只在等式满行秩已有
reduced-space 证明后用于 condensed 路径；Conic 固定精化改为
Dembo-Eisenstat-Steihaug forcing gate。开放 HS071 上 Native 与 Ipopt 均准确，
Native 热运行 0.295–0.402 ms、Ipopt 2.037–2.273 ms；OPF 结构探针上 Native
仍为 25.7–32.7 ms、Ipopt 15.4–17.5 ms，作为未解决负结果保留。完整推导与
审计数据见 `docs/ipm_structural_performance_2026-08-06.md`。

这说明可迁移的是决策框架，而不是某个 LP 路由：

1. 候选生成来自锥/约束局部结构；候选选择来自完整消元图。
2. symbolic 只比较同一后端语义；后端必须匹配 SPD/对称不定结构。
3. 精化由同坐标后向误差触发，不能固定次数执行。
4. 正结果与长尾负结果都必须用原模型 KKT 审计和等价基准固化。

## 8. 路线图：按理论收益 × 工程风险排序

延续仓库合同文化：每项列收益模型、验收 gate。R1–R3 是纯工程项（无算法风险），R4–R6 是有理论收益模型的性能项，R7–R8 是战略项。

- **R1 平台性能地板（最高优先，纯工程）**：Linux x86 CI + 性能矩阵；为增广 KKT 在非 Apple 平台补多线程路径（CHOLMOD supernodal 拟定模式或 PARDISO）；NEON 内核补 AVX2 等价或改用可移植 SIMD 抽象。收益模型：消除 4–10× 静默平台悬崖（§5.2）。gate：同一 case 集双平台墙钟比 ≤1.5×。
- **R2 METIS/ND 排序选项（最高性价比性能项）**：CHOLMOD Partition 模块 + vendored METIS（构建级）；符号分析期 AMD/ND 双试排取 nnz(L) 小者（analyze-once 摊销）。收益模型：墙钟 ∝ fill 膨胀率 φ，SCUC 尺度 φ∈[1.5,5]（§3.1）。gate：大规模 case 上 nnz(L) 与 factor 墙钟双降，小规模无回归。
- **R3 并发解锁**：MUMPS 互斥改实例池/按需多进程；发布各后端线程安全合同文档。收益模型：跨节点/跨场景尴尬并行，speedup ≈ min(并发数, 负载数)。gate：并行 B&C 双线程 ≥1.7×，数值路径不变式保持。
- **R4 多 RHS 块回代（IPM）**：Gondzio 校正组 + 精化残差组块化，CHOLMOD `solve2`/Accelerate 多列。收益模型：backsolve 占 IPM 迭代份额 s（仪表可测），bytes 摊薄 → 节省 ≈ s·(1−1/k)。gate：iters 不变、逐迭代 solve 桶墙钟下降。
- **R5 GMRES-IR 精化层**：替换/包裹 `kkt_system.cpp:266-277` 与 LP 精化的固定 Richardson。收益模型：收敛包络 κ·u_f<1 → κ·u≈1；直接收益是病态末期少触发正则化升档/重分解，同时是 R6 使能件。gate：现有全部精化触发 case 迭代数不增、失败率下降。
- **R6 相位自适应混合精度（IPM，R5 后）**：μ 与 κ 估计门控的 FP32 分解 + FP64 GMRES-IR，末期强制 FP64。收益上界 2×（§3.4），综述 §4.1 警示的误差验证成本高——排在 R2/R4 之后。单纯形明确豁免。gate：全 suite 精度合同 + 混合精度专用扰动测试组。
- **R7 批处理 API 预留（战略）**：在 `SparseLinearSolver`/IPM 缓存层定义"同模式多矩阵/多 RHS"接口形态（对齐 cuDSS/SuperLU 9.0 batched 语义），当前用 CPU 循环实现。目的：使 R8 的 GPU 决策成为后端替换而非架构重构。
- **R8 GPU：显式推迟并记录重启条件**：按综述 §2.4/§5.5 证据，MA57 域（中小规模病态不定）CPU 仍最优，cuDSS 优势域是"大规模 + 符号复用 + 高频重分解"。重启条件：单 LP m ≥ 10⁵⁻⁶ 且呈现该复用形态，或产品目标转向大规模 OPF/SCOPF（届时走凝缩 KKT + cuDSS 路线，而非移植现有不定分解）。
- **R9 基准广度**：纳入 Mittelmann LP 子集与 SuiteSparse 电网矩阵族（综述 §6.3 挑战三所指缺口的本地版本），SCUC 规模梯度（39/118/300-bus×时段数）进入度量合同——否则 R2/R4/R6 的收益在 NETLIB-24 上不可见（其收益全部随规模增长）。

## 9. 结语

综述给出的历史规律是"每一次算力阶跃对应求解器技术的一次范式更新"，且当下的增量性能来源已明确迁移到"GPU 原生化、批处理化、预条件复用、精度分层"。以此为坐标系，本内核的真实位置是：**在上一个范式（CPU 串行 FP64 直接法）内做到了接近极限且在可靠性维度超配，但对当前范式的四条增量轴（排序、并行、批处理、精度）尚未开始兑现**。"研究级"的感受来自后者；而前者意味着工程化不需要推倒重来——R1–R4 四项（平台地板、ND 排序、并发解锁、块回代）没有任何算法风险，合计即可把内核从"开发机上的优秀原型"变为"部署矩阵上的可预期产品"，其后的精度分层与 GPU 决策再按规模证据触发。
