# PowerSimulationsDynamics.jl Interop Workflow

Date: 2026-07-04

This is the next validation layer after the first PSD trace checks: keep the
HACDCPF hybrid AC/DC runtime, but make PSD/PowerSystems data and results
first-class comparison artifacts.

## Direction

Use `PowerSimulationsDynamics.jl` as the reference implementation for dynamic
model/controller behavior, not as a replacement for HACDCPF. PSD cases enter the
HACDCPF validation harness through two neutral artifacts:

1. **Input snapshot**: `hacdcpf_psd_snapshot.v1`, generated by
   `tools/psd_validation/export_psd_snapshot.jl`. This captures the PSD
   `PowerSystems.System` static objects, `DynamicInjection` devices, and their
   machine/shaft/AVR/governor/PSS or inverter subcomponent slots.
2. **Output trace**: `time_s,value` CSV, generated by the existing
   `tools/psd_validation/export_trace.jl`. This is the common time-series shape
   used by the current external comparison tests.

The snapshot is intentionally a comparison manifest, not a claim that every PSD
network feature can already be imported into HACDCPF. The model identity is
preserved even when the runtime implementation is still missing.

## Comparison Ladder

| Level | Meaning | Artifact |
|---|---|---|
| L0 | Preserve model/controller identity only | Snapshot + crosswalk row |
| L1 | Single model or controller trace | PSD CSV + HACDCPF CSV |
| L2 | Composed device trace | Dynamic injection slot snapshot + trace |
| L3 | Small system trace | Event manifest + multi-signal traces |
| L4 | Residual/mass-matrix or small-signal parity | Future DAE API and eigenvalue report |

## Practical Rule

Every PSD model/controller should have one of four explicit statuses:

- `exact-or-close`: compare traces directly after base/sign/time alignment.
- `supported-subset`: compare selected signals and document omitted PSD blocks.
- `profile-only`: round-trip identity and parameters, but do not compare dynamic
  behavior yet.
- `missing`: preserve source identity and create a model-library task.

The generated report at `tools/psd_validation/psd_model_comparison.md` is now the
working ledger for model/controller identity. The component-test stop/go report
is `tools/psd_validation/psd_component_test_matrix.md`; as of July 4, 2026 it
does not pass as a full suite because many PSD machine and IBR component families
are not implemented in HACDCPF yet.
