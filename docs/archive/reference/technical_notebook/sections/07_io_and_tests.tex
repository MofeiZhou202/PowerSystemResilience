\subsection{MATPOWER Parser}
\label{sec:matpower-parser}
% ------------------------------------------------------------

\texttt{hacdcpf::io::parse\_matpower(path)} reads MATPOWER \texttt{.m} case files
from disk (\texttt{include/hacdcpf/io/matpower\_parser.hpp}).  The parser
understands the \texttt{mpc.version~=~'2'} format used by MATPOWER~6 and
populates a \texttt{HybridPowerSystem} object.

\paragraph{Covered table sections}
\begin{longtable}{L{0.22\linewidth}L{0.70\linewidth}}
\toprule
Section & Mapped struct(s) \\
\midrule
\endhead
\texttt{mpc.bus} & \texttt{ACBus} (type, Pd, Qd, Gs, Bs, Vm, Va, Vmin, Vmax). \\
\texttt{mpc.gen} & \texttt{Generator} (bus, Pg, Qg, Qmax, Qmin, Vg, Pmax, Pmin, status). \\
\texttt{mpc.branch} & \texttt{ACBranch} (from, to, r, x, b, rateA/B/C, tap, shift, status). \\
\texttt{mpc.gencost} & Generator cost model: polynomial (type 2) or piecewise-linear (type 1). \\
\texttt{mpc.dcline} & \texttt{VSCConverter} (basic two-terminal DC; mapped to converter pair). \\
\texttt{mpc.bus\_name} & Populates \texttt{ACBus::name}. \\
\bottomrule
\end{longtable}

Data directory \texttt{data/} ships with 80+ MATPOWER case files covering
IEEE~9, 14, 30, 57, 118, 300, and a range of synthetic US/European grids up to
82\,000 buses.

\subsection{JSON I/O}
\label{sec:json-io}
% ------------------------------------------------------------

\texttt{include/hacdcpf/io/json\_io.hpp} provides the always-built JSON API:
\begin{itemize}
  \item \texttt{to\_json(sys)} / \texttt{from\_json(json)} and
        \texttt{save\_json(sys,path)} / \texttt{load\_json(path)} for
        \texttt{HybridPowerSystem};
  \item \texttt{try\_from\_json(json,mode)} and
        \texttt{try\_load\_json(path,mode)} for exception-free import using
        \texttt{Result<HybridPowerSystem>};
  \item \texttt{to\_jpc\_json(sys)} / \texttt{from\_jpc\_json(json)} and
        \texttt{save\_jpc\_json} / \texttt{load\_jpc\_json} for the
        MATPOWER-like JPC JSON interchange format;
  \item \texttt{power\_flow\_result\_to\_json(sys,result)} and
        \texttt{save\_power\_flow\_result\_json(sys,result,path)} for PF
        results;
  \item \texttt{opf\_result\_to\_json(result)} /
        \texttt{opf\_result\_from\_json(json)} and
        \texttt{save\_opf\_result\_json} / \texttt{load\_opf\_result\_json}
        for AC OPF results;
  \item \texttt{dc\_opf\_result\_to\_json(result)} /
        \texttt{dc\_opf\_result\_from\_json(json)} and corresponding
        save/load helpers for DC OPF results;
  \item \texttt{carbon\_result\_to\_json(result)} /
        \texttt{carbon\_result\_from\_json(json)} and save/load helpers for
        carbon-analysis results;
  \item \texttt{time\_series\_data\_to\_json(ts)} /
        \texttt{time\_series\_data\_from\_json(json)} for time-series input
        data.
\end{itemize}
The on-disk schema is sparse-friendly: optional arrays may be absent, identity
and connectivity fields are generally required, and schema compatibility is
checked through \texttt{check\_schema\_version}.  The detailed key-level
contract is maintained in Sections~\ref{sec:io_contracts} and
\ref{sec:output_field_dictionaries}.

Excel I/O remains optional.  The public header declares
\texttt{load\_excel}/\texttt{save\_excel}; without
\texttt{HACDCPF\_ENABLE\_EXCEL} these inline functions throw.  When Excel
support is compiled, \texttt{src/io/excel\_io.cpp} also contains source-level
workbook helpers such as \texttt{load\_xlsx}, \texttt{save\_xlsx},
\texttt{save\_results\_xlsx}, \texttt{save\_results\_compact\_xlsx},
\texttt{save\_opf\_results\_xlsx}, \texttt{save\_opf\_results\_compact\_xlsx},
and \texttt{save\_carbon\_results\_xlsx}.

\paragraph{Model compatibility and digital-twin governance.}
The GUI-facing endpoint \texttt{/api/io/model\_compatibility} now returns the
component compatibility registry, current-system coverage, GridLAB-D/OpenDSS
diagnostics, the parameter-rule catalog, the parameter audit report, the
digital-twin readiness criteria, and the current digital-twin readiness report.
The C++ entry points are documented in
Section~\ref{sec:io_governance_digital_twin}.  This endpoint is intentionally
used by both the dedicated \texttt{Data IO} panel and transient-compatibility
launch points so import/export, standards, parameter health, and twin maturity
remain in one user-facing report.

\subsection{Pre-built Test Networks (\texttt{case\_builders.hpp})}
\label{sec:case-builders}
% ------------------------------------------------------------

\texttt{hacdcpf::io} exposes a library of factory functions for use in tests
and benchmarks.  Most named \texttt{\_acdc} builders add a DC overlay and VSC
links; \texttt{build\_ac\_only\_version} strips those components, and
\texttt{build\_market\_3bus\_toy} is intentionally AC-only for market/DCOPF
unit tests.

\begin{longtable}{L{0.44\linewidth}L{0.50\linewidth}}
\toprule
Function & Description \\
\midrule
\endhead
\texttt{build\_ieee14\_acdc()} & IEEE 14-bus AC + one DC link. \\
\texttt{build\_ieee24\_3area\_acdc()} & IEEE 24-bus RTS divided into 3 control areas, interconnected via DC. \\
\texttt{build\_ieee24\_3area\_acdc\_expanded()} & Expanded version with additional DER and storage. \\
\texttt{build\_ieee118\_acdc()} & IEEE 118-bus + multi-terminal DC grid. \\
\texttt{build\_ac\_only\_version(sys)} & Strip all DC components from an existing system. \\
\texttt{build\_case33bw\_acdc()} & Baran--Wu 33-bus distribution + DC microgrid. \\
\texttt{build\_case33mg\_acdc()} & 33-bus microgrid variant with storage. \\
\texttt{build\_case69\_acdc()} & 69-bus radial distribution + DC feeder. \\
\texttt{build\_case300\_acdc()} & IEEE 300-bus + HVDC link. \\
\texttt{build\_demo\_multizone\_acdc()} & Multi-zone demonstration system. \\
\texttt{build\_case2000\_acdc()} & 2000-bus synthetic + DC overlay. \\
\texttt{build\_dist33\_microgrid\_der()} & 33-bus distribution with DER and battery storage. \\
\texttt{build\_comprehensive\_hybrid\_acdc()} & Stress-test system with all component types. \\
\texttt{build\_market\_3bus\_toy()} & 3-bus toy system for market/OPF unit tests. \\
\texttt{build\_market\_5bus\_acdc\_toy()} & 5-bus AC/DC toy for hybrid OPF unit tests. \\

\section{Test Suite}
\label{sec:tests}
% ============================================================

All tests use the Catch2 framework supplied by the local MIPSolvers source
tree; configuration performs no network fetch.  The current macOS release tree used by GUI and IO
verification is \texttt{build/macos-release}; build and run focused IO checks
with:
\begin{verbatim}
cmake --build build/macos-release --target run_gui_server test_component_io_mapping -j8
./build/macos-release/tests/test_component_io_mapping
node --check web/js/app.js
node --check web/js/components.js
\end{verbatim}
For a full CTest sweep, run the configured release tree directly with
\texttt{ctest --test-dir build/macos-release --output-on-failure}.

\subsection{Example Test Pattern}
% ------------------------------------------------------------

The typical Catch2 test pattern in this project:

\begin{verbatim}
TEST_CASE("brief description", "[tag1][tag2]") {
    auto sys = hacdcpf::io::build_ieee14_acdc();
    hacdcpf::PowerFlowOptions opt;
    opt.tol = 1e-8;

    auto result = hacdcpf::solve_power_flow(sys, opt);

    REQUIRE(result.converged);
    REQUIRE_FALSE(result.vm.empty());
    REQUIRE_THAT(result.vm[0],
                 Catch::Matchers::WithinAbs(1.0, 0.1));
}
\end{verbatim}

Tags used across the suite include \texttt{[model]}, \texttt{[power\_flow]},
\texttt{[opf]}, \texttt{[integration]}, \texttt{[io]}, \texttt{[matpower]},
\texttt{[validation]}, \texttt{[topology]}, \texttt{[graph]},
\texttt{[resilience]}, \texttt{[reliability]}, \texttt{[short\_circuit]},
\texttt{[three\_phase]}, \texttt{[performance]}, and \texttt{[scaling]}.
Section~\ref{sec:test_results} gives the current 436-entry CTest registration
with exact Release IDs and pass/skip status.
