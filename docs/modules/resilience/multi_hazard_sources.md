# 多灾害场景：参考书覆盖与开源模型调研

状态：**调研与接入设计**。核实日期：2026-09-27。
后续已实现按设备分类的暴雨内涝与雷击简化生成器，当前行为以[实现契约](weather_scenarios.md)为准。
本页保存选型依据和其余灾种规划；表中外部模块尚未集成。
本次核验参考书正文、现有源码、上游说明、部分源码与许可证；未安装或运行候选求解器。

## 2. 当前代码与真正缺口

- `include/hacdcpf/analysis/scenario_generation.hpp` 的 `ResilienceEventDefinition`
  使用 `TyphoonIntensityCategory`、台风路径、`TyphoonBranchRisk` 和 `*_typhoon_multiplier`，
  新灾种不能仅增加下拉选项后继续把强度解释成风速。
- `src/scenario_generation/typhoon_resilience.cpp` 已提供台风场景链。
  `ScenarioCandidate` 的时序、候选集、代表场景与概率组织可作为共用部分。
- `include/hacdcpf/analysis/typhoon_traffic_impact.hpp` 与对应 `.cpp` 已有台风降雨、
  路段零维产流/排水蓄水、积水深度到车速和封路的影响。可复用积水与交通接口；
  这不代表已接入独立暴雨生成器，也不代表有地形驱动的二维洪水求解。
- `include/hacdcpf/resilience/resilience_assessment.hpp` 的 `DistributionResilienceFault`
  表达 AC/DC 支路稳定索引、故障起始时间和修复时长。
  变电设备损伤、机组降额、控制不可用等需要新的类型与求解器消费路径，不能一律伪装成断线。
- `include/hacdcpf/resilience/certified_restoration.hpp` 有指令路径、授权与确认的可执行性约束，
  可以作为信息侧影响的设计参考；尚未证明这些功能已经贯通当前 Web 场景主流程。

## 4. 统一接入契约草案

建议统一链路：灾害参数/实测数据 → 时空强度场 → 资产暴露与脆弱性 →
故障/降额/交通/控制时序 → 场景缩减 → 恢复求解 → 指标结果。

1. **灾害描述**：灾种、子事件及相关关系、随机种子、时间轴、坐标系、强度字段与单位、
   模型版本、参数和数据来源。Canvas 绘图坐标不能默认视为真实经纬度或地形。
2. **事件概率**：区分给定灾害下样本权重、年发生率和观测窗发生概率。
   复合事件保留共同气象驱动/条件关系，不把相关事件的概率简单相乘。
3. **设备影响**：`domain + component_kind + stable_index`，明确暂时跳闸、永久损坏、
   降额、量测不可用、控制不可用；附故障时间、损伤等级、修复时长/资源和安全开工时间。
   非支路设备必须有真实求解消费路径，未贯通时返回 unsupported。
4. **连续影响**：发电可用率、线路容量、负荷、来水/能量预算、道路通行、控制可执行性。
   每个向量声明步长、单位、索引空间与原始设备归属。保留台风旧接口兼容层。
5. **三个不同时间**：指标计算的灾害结束默认仍遵从用户指定的“最后一个故障发生时刻”；
   危险环境结束/安全开工和最后维修完成另记。雷电尚未结束时不能因统计结束时刻已到就允许抢修。
6. **有效性**：返回实际使用的模型、近似、缺失数据、适用灾种和组件范围；
   缺少地形/脆弱性数据时只能采用明确标注的简化研究模型，不能声称复现了 SWMM/ANUGA 等求解。

## 5. Web 方案及交付顺序

平台名称保持“弹性仿真平台”。场景页建议先选灾种卡片，再选演示/参数生成/数据导入，
按灾种显示少量关键参数，高级参数折叠。每种事件显示参考书位置与实际模型范围。
模型未接通前不提供会产生伪结果的可运行按钮。

结果页提供对应强度过程、影响分布、设备故障时间线、修复条件、风光负荷变化与代表场景。
地图仅在坐标和范围有效时显示；计算摘要继续置于页尾并默认折叠。

交付建议：

1. **公共事件结构和暴雨/雷电**：优先覆盖书中详细自然灾害模型；雨量—积水—受淹与
   雷暴—闪络—跳闸/永久故障分别闭环，复用现有候选/缩减/恢复/指标流程。
2. **人为事件及高温/极寒/干旱/覆冰**：加入设备与信息侧失效，以及供给、负荷、容量和
   抢修环境的影响。复合场景支持台风叠加暴雨、高温叠加干旱。
3. **地震、山火、海啸**：接入可选空间模型和设备损伤适配，准备可复现的小型地理案例。
4. **地磁暴与电磁扰动**：先补 GIC 和设备模型所需数据，再做物理验证；E1/E2 未实现时明确标记。
   日食作为新能源出力扰动单独接入。以上覆盖范围不会因实施顺序而删去。

已有 42 项指标目录继续复用，按实际输入逐项判断可计算性。新增灾种不会自动使全部指标可用；
多场景风险指标还需要真实逐场景恢复求解、权重口径与聚合，不能只凭灾害强度计算。

## 6. 后续实现的验收要求

- 每个生成器提供公式/来源、参数单位、源码、自动测试与可复现小案例。
- 强度到损伤检查零暴露、极值、概率边界及合理的单调性；同一种子可复现。
- 时间检查故障先后、暂时跳闸恢复、安全开工和维修结束；持续影响不被错误丢弃。
- 空间检查坐标系、单位、场外设备和 AC/DC 同号稳定 ID。
- 外部模块先运行其小算例，再检查双方共同模型范围；不能仅凭安装成功声明数值正确。
- 端到端验证实际 Web 生成→选择→恢复→指标；不支持的设备影响应显式拒绝。
- 本次仅完成上述调研和设计记录，没有新数值算法、外部求解器运行或新增灾种 E2E 结果。
