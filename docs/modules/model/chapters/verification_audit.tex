\subsection{剩余观察边界}

现有审计仍提示的工程债务包括：部分 dead public API、组件同义字段命名差异、宏设备/三相投影的
不可逆信息、参数来源多层、某些动态和可靠性字段仅被特定模块消费，以及结果终端符号跨族不统一。
这些观察不能自动解释为当前数值缺陷，但在新增工作流时必须重新审计。

\subsection{变更准入清单}

\begin{enumerate}
  \item 新字段必须声明单位、符号、稳定身份/端子和参数所有者；
  \item 为每个相关 workflow 更新 \texttt{component\_runtime\_semantics()}；
  \item 更新 JSON/外部格式映射，明确缺失与回退，不静默伪造来源；
  \item 若进入 canonical，补 projection provenance、AC/DC 同号、dead island 和幂等测试；
  \item 若结果可见，补 Strong/Approximate/AuditOnly/Unsupported 归因及索引空间；
  \item 若改变方程或容量语义，同步下游 PF/OPF/可靠性/弹性/市场/时序手册和回归；
  \item 运行 \texttt{git diff --check}、聚焦测试及可承受的完整 Release CTest，分别记录未执行项。
\end{enumerate}

\subsection{验证口径}

现有开发状态中模型数学审计的历史 Debug 证据与当前 Release 树并非同一构建。本文档改写不改变 C++ 行为；
本轮会重跑可用的聚焦目标并单独记录。未运行 sanitizer、全量 CTest 或外部工具时，不得把“手册编译通过”
写成模型算法验证。

\subsection{工业应用边界}

模型层只保证数据表示和已执行转换的契约，不保证输入真实、状态可观、方程适定、优化全局最优或控制安全。
生产应用至少还需数据来源审计、所需 validation level、投影证书、具体分析的 validity/model scope、
独立残差或交叉引擎证据，以及结果到稳定资产 ID 的完整归因。
