\subsection{工业准入条件}
生产报告只有在以下条件同时满足时才标为“可审计年度结果”：
\begin{enumerate}
  \item 输入 profile 长度与 $T$ 一致，单位和时间基准（UTC/本地、闰年与否）已记录；
  \item 记录 \texttt{solver\_name}、\texttt{solver\_status}、MIP gap、\texttt{optimality\_proven}、
        daily/weekly 模式及 cyclic SOC 设置；
  \item 对物理年度结果，\texttt{skip\_replay=false} 且报告 PF/OPF 收敛计数、最大残差、
        支路/换流器负载和 \texttt{power\_balance\_error\_mwh}；
  \item 若使用生命周期层，报告输入 \texttt{TimeSeriesData.step\_duration\_hr}（不能以未消费的
        option 代替）、碳因子口径、三项 bound 和 dense-vs-sampled gap，并明确其 schedule-only 范围；
  \item 含扩展组件时，单独给出其 dispatch/energy 归因；若没有，则必须标注
        \texttt{component economics outside annual perimeter}，禁止宣称闭环；
  \item 依赖版本（尤其兄弟仓库 MIPSolvers commit）和测试命令写入验证记录。
\end{enumerate}

\subsection{尚未闭环但可复现的研究问题}
\begin{itemize}
  \item 将燃料热率、燃料类型和真正燃料库存替代当前的发电量 MWh 代理；
  \item 以滚动 SOC 链替代强制日/周循环，量化季节储能的分解差距；
  \item 增加制造/材料碳、网络损耗碳和换流器库存的明确来源；
  \item 用随机抽样重复试验建立统计 coverage，而不是把确定性分层 bound 写成置信保证；
  \item 将 VPP、微网、移动储能、EnergyRouter、DR 的 schedule 行加入年度/生命周期 accounting；
  \item 为年度结果建立外部参考（生产成本模型或逐时 OpenDSS/商业 SCUC），而不是把 PF 引擎当 UC 参考。
\end{itemize}
