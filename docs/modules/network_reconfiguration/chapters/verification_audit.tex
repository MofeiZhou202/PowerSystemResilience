\section{验证矩阵与系统审计}\label{sec:nr-verification}

\subsection{审计范围}

本轮逐段核对：
\begin{itemize}
  \item 两个公共头的全部类型、默认值、注释与入口；
  \item \srcpath{topology\_reconfiguration.cpp} 的全部 1949 行可达核心路径；
  \item \srcpath{topology\_analysis.cpp} 的查询、兼容包装和包装后不可达旧模型；
  \item CMake 源文件接线、五个直接/交叉测试目标；
  \item \srcpath{POST /api/session/run\_reconfig} 的请求映射、富模型回投影、PF/OPF 与 JSON；
  \item web/e2e 消费点、理论速查、模块文档地图和审计台账。
\end{itemize}
“Deep”表示公共接口、核心实现、失败/结果语义和注册测试均已检查；不表示所有网络规模、所有求解器
组合或所有富设备类型都已动态穷举。

\subsection{覆盖充分的契约}

已有直接回归锁定：
\begin{itemize}
  \item AC/DC 同号 ID 使用 \texttt{BranchRef} 消歧；旧 AC 整数候选不会误操作 DC；
  \item ExternalGrid-only、DC-only 源与无源失败；
  \item AC bus demand + Load、DCBus demand + DCLoad 的加法聚合；
  \item 分域 AC/DC 树、VSC bridge 自由、DC mesh 和 DC 独立开环；
  \item Fuse 不参与即时恢复、tie 直接闭合、隔离设备上游 trip/operate/reclose；
  \item 6-bus 与穷举、33-bus 与后续 PF/配电 PF、跨模块 OPF/PF/碳流；
  \item verbose=false 不向 stdout/stderr 泄漏求解器诊断。
\end{itemize}

\subsection{动态覆盖缺口}

本轮新增回归已锁定 solver 后端分派（NR-03）、核心 \fld{base\_loss\_mw}/reduction 代理与 HTTP
\texttt{estimated\_loss\_mw} 口径（NR-04/NR-01）、\fld{ValidityFlags} 的 DC mesh 与空系统口径（NR-02）、
以及 ONR 回退可观察标志 \fld{fallback\_used}（NR-05）。下列高风险契约仍无直接、专门的断言：
\begin{itemize}
  \item \texttt{scip} 后端在可用时的求解路径与状态/gap 规范化（native 已知在该 MILP 上偏弱，仅测分派）；
  \item 图启发式成功路径的 \fld{proven\_optimal=false} 和无限 gap；
  \item 后端返回成功但后验等式/不等式/整数性/变量界失败的拒绝分支；
  \item 负权重、$v_{min}>v_{max}$、非正容量、未知 solver、未匹配故障 ID 的输入拒绝；
  \item 切负荷不超过节点需求、P/Q 同比例削减和纯无功/负负荷边界；
  \item CircuitBreaker 的锁定/操作能力与 Switch 规则的一致性；
  \item HTTP \fld{executable} 的注册生产路由专项 E2E；现有参数库脚本未注册到 CMake。
\end{itemize}

\subsection{已关闭审计发现}

以下 NR-01--NR-06 已在本轮实现修复并回归，登记为 AUD-018--023；全套回归及完整 1690/1690 见
第~\ref{sec:nr-numerical-crossval} 节口径。

\subsubsection{NR-01：HTTP estimated loss 口径（已修复）}

\srcpath{run\_gui\_server.cpp} 的 \texttt{estimated\_loss\_mw} 不再写 \fld{milp\_objective}$\times S_B$，
改为核心显式定义的名义电流损耗代理 \fld{reconf\_loss\_mw}（MW）；真实损耗仍是独立的 PF 后验证
\texttt{base\_loss\_mw}/\texttt{reconfig\_loss\_mw}（仅 \texttt{reconfig\_pf\_converged=true} 时有效）。

\subsubsection{NR-02：ValidityFlags 口径（已修复）}

\fld{radial\_topology\_enforced} 现为 $\lnot(\texttt{split\_domain\_trees}\lor\texttt{allow\_dc\_mesh})$，
空系统提前返回时清空全部 \fld{ValidityFlags}。头注释区分：\fld{*\_enforced}/\fld{*\_modelled} 为本次求解的
formulation 属性，\fld{*\_validated}/\fld{executable} 为后验证结果，对直接核心求解恒为 false（表示“核心未
验证”，非被掩盖的失败）。回归 \srcpath{test\_reconfig\_options} NR-02。

\subsubsection{NR-03：solver 注释与实际口径（已修复）}

\texttt{TopoReconfOptions::solver} 与 \texttt{topology\_analysis.hpp} 注释已与运行一致：\texttt{auto}
与 \texttt{highs} 均为 HiGHS$\to$SCIP，\texttt{native}/\texttt{scip} 为单后端；native B\&C 在该
LinDistFlow MILP 上弱于 HiGHS，为 opt-in 而非自动 fallback，行为未变。ONR 包装头注释已改为“经
\srcpath{run\_topology\_reconfiguration}（solver=highs）”。回归 \srcpath{test\_reconfig\_options} NR-03 校验分派后端。

\subsubsection{NR-04：核心字段赋值（已修复）}

\fld{base\_loss\_mw}、\fld{loss\_reduction\_mw}、\fld{loss\_reduction\_pct} 现于核心按与 \fld{reconf\_loss\_mw}
相同的名义电流代理赋值（base 对初始在运支路求和），直接 C++ 调用得到已定义值而非静默 0；头文件标注其为
代理，区别于 HTTP 的 PF 字段。后验证/可执行标志对核心求解保持 false（“核心未验证”）。回归
\srcpath{test\_reconfig\_options} NR-04。

\subsubsection{NR-05：历史 ONR 回退标记（已修复）}

新增 \fld{ONRResult::fallback\_used}，核心 MILP 失败但原拓扑 PF 收敛时置真（\fld{feasible} 真、
\fld{optimal} 假、目标 0）；头注释声明其为连通性回退而非 ONR incumbent。回归 \srcpath{test\_topology\_crossval}

\subsubsection{NR-06：旧 AC MILP 不可达实现（已删除）}

\srcpath{topology\_analysis.cpp} 兼容包装 return 之后的 629 行不可达历史 B\&C 已删除，
\texttt{solve\_optimal\_reconfiguration(ACSystem)} 现只有一个可达模型（混合包装），头注释不再声称直接
native B\&C。回归 reconfig 全套（91+54 assertions）绿，库重建无不可达代码错误。

\subsection{已知模型边界}

\begin{itemize}
  \item 单时刻、稳态、正序/平衡等值；无三相相域拓扑变量；
  \item LinDistFlow 不含支路损耗，P/Q 热限为矩形，VSC 有功无效率损耗且 Q 只接 AC 端；
  \item \fld{loss\_aware} 是 $r|P|$ 线性代理，不是 $I^2R$；默认非 loss-aware 更只是 $r\beta$；
  \item 根与源容量是聚合近似，ExternalGrid 能力以短路容量或默认容量替代运行限额；
  \item 切负荷无需求上界与恒功率因数联动；
  \item 设备能力只对投影可归因的 AC Switch/CircuitBreaker 较完整，DC/VSC 结构化候选是分支级；
  \item 保护联锁是静态元数据规则，不含短路电流、保护配合、同步或操作时延；
  \item 结果不包含逐母线电压/切负荷、逐边 P/Q、对偶量、下界、约束残差和模型限制列表；
  \item 核心不执行完整 PF/OPF，兼容 ONR 只验证 AC PF，HTTP 才追加 PF/AC OPF；
  \item 旧整数 ID 结果不适用于 AC/DC/VSC 同号系统。
\end{itemize}

\subsection{工业使用判据}

把结果用于运行建议前，至少应满足：
\begin{enumerate}
  \item 输入通过严格 validation，故障与候选稳定 ID 全部匹配；
  \item 使用 \texttt{BranchRef}，并保存实际 solver/backend/status/gap；
  \item \fld{feasible=true}；若宣称最优，还须 \fld{proven\_optimal=true}；
  \item 动作已回投影、\fld{switch\_sequence\_valid=true}；
  \item 富模型重投影后 AC/DC 拓扑符合业务要求；
  \item 完整 PF 收敛并满足电压/热限，所需场景下完整 OPF 也收敛；
  \item 损耗来自收敛 PF，而非目标或名义电阻代理；
  \item 对关键故障做备用动作、保护配合和现场可操作性复核。
\end{enumerate}
