\subsection{MATPOWER Parser}
\label{sec:matpower-parser}
% ------------------------------------------------------------

\texttt{hacdcpf::io::MatpowerParser} reads MATPOWER \texttt{.m} case files
from disk (\texttt{include/hacdcpf/io/matpower\_parser.hpp}).  The parser
understands the \texttt{mpc.version~=~'2'} format used by MATPOWER~6 and
populates a \texttt{HybridPowerSystem} object.

\paragraph{Covered table sections}
\begin{longtable}{L{0.22\linewidth}L{0.70\linewidth}}
\toprule
Section & Mapped struct(s) \\
\midrule
\endhead
\texttt{mpc.bus} & \texttt{ACBus} (type, Pd, Qd, Gs, Bs, Vm, Va, Vmin, Vmax). \\
\texttt{mpc.gen} & \texttt{Generator} (bus, Pg, Qg, Qmax, Qmin, Vg, Pmax, Pmin, status). \\
\texttt{mpc.branch} & \texttt{ACBranch} (from, to, r, x, b, rateA/B/C, tap, shift, status). \\
\texttt{mpc.gencost} & Generator cost model: polynomial (type 2) or piecewise-linear (type 1). \\
\texttt{mpc.dcline} & \texttt{VSCConverter} (basic two-terminal DC; mapped to converter pair). \\
\texttt{mpc.bus\_name} & Populates \texttt{ACBus::name}. \\
\bottomrule
\end{longtable}

Data directory \texttt{data/} ships with 80+ MATPOWER case files covering
IEEE~9, 14, 30, 57, 118, 300, and a range of synthetic US/European grids up to
70\,000 buses.

% ------------------------------------------------------------
\subsection{JSON I/O}
\label{sec:json-io}
% ------------------------------------------------------------

\texttt{include/hacdcpf/io/json\_io.hpp} provides:
\begin{itemize}
  \item \texttt{load\_hybrid\_system\_from\_json(path)} -- read a
  \texttt{HybridPowerSystem} from disk;
  \item \texttt{save\_hybrid\_system\_to\_json(sys, path)} -- write to disk;
  \item \texttt{result\_to\_json(result)} -- serialise a
  \texttt{PowerFlowResult} to JSON;
  \item \texttt{opf\_result\_to\_json(result)} -- serialise an
  \texttt{OPFResult}.
\end{itemize}
The on-disk schema mirrors the field names of the C++ structs and includes
metadata (\texttt{name}, \texttt{base\_mva}, timestamps).

\section{Test Suite}
\label{sec:tests}
% ============================================================

All tests use the Catch2 framework (fetched automatically by CMake via
\texttt{FetchContent}).  Build and run with:
\begin{verbatim}
cmake -B build -DHACDCPF_BUILD_TESTS=ON
cmake --build build
cd build && ctest --output-on-failure
\end{verbatim}

\subsection{Example Test Pattern}
% ------------------------------------------------------------

The typical Catch2 test pattern in this project:

\begin{verbatim}
TEST_CASE("brief description", "[tag1][tag2]") {
    auto sys = hacdcpf::io::build_ieee14_acdc();
    hacdcpf::PowerFlowOptions opt;
    opt.tol = 1e-8;

    auto result = hacdcpf::solve_power_flow(sys, opt);

    REQUIRE(result.converged);
    REQUIRE_THAT(result.buses[0].vm_pu,
                 Catch::Matchers::WithinAbs(1.06, 1e-4));
}
\end{verbatim}

Tags used across the suite include \texttt{[model]}, \texttt{[pf]},
\texttt{[opf]}, \texttt{[integration]}, \texttt{[enhanced]}, \texttt{[island]},
\texttt{[performance]}, and \texttt{[scaling]}.
