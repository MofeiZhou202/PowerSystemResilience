% ============================================================
\section{EV Power--Traffic Coupled Simulation: Implemented Model and Solver-Certified Extension}
\label{sec:ev_power_traffic_dynamic_model}
% ============================================================

This chapter documents the mathematical model that is currently
implemented in the \texttt{hacdcpf::evpt} module and then gives the
solver-certified dynamic joint-optimization formulation that is now
fully implemented and validated.  All four formulations (A--D) have
direct code counterparts in the current source tree.  The regression
test suite (\texttt{test\_ev\_power\_traffic.cpp},
\texttt{test\_ev\_power\_traffic\_report.cpp},
\texttt{test\_ev\_power\_traffic\_joint\_opt.cpp},
\texttt{test\_ev\_power\_traffic\_largescale.cpp},
\texttt{test\_ev\_power\_traffic\_ctm\_due.cpp},
\texttt{test\_ev\_power\_traffic\_joint\_opt\_d.cpp}) provides
reproducible numerical values for Formulations~A--D that are used as
the running examples in this chapter.

\paragraph{Modeling formulation tiers.}
To avoid confusion between what is currently implemented and what
represents a future extension, this chapter uses four explicitly
named tiers:

\begin{description}
  \item[Formulation~A (implemented, validated).]
    Static BPR traffic model; free-flow precomputed route arrival steps;
    fixed charging-profile system-optimal LP/MILP with demand-balance,
    road-capacity, and station-power constraints; optional DC-OPF
    coupling via iterative LMP-price update.  Validated by
    \texttt{test\_ev\_power\_traffic.cpp},
    \texttt{test\_ev\_power\_traffic\_report.cpp},
    \texttt{test\_ev\_power\_traffic\_joint\_opt.cpp}, and
    \texttt{test\_ev\_power\_traffic\_largescale.cpp}.
  \item[Formulation~B (implemented, validated).]
    Daganzo CTM with triangular fundamental diagram; route-specific
    (commodity) cell occupancy to preserve station-choice identity through
    diverge nodes; MSA-based Dynamic User Equilibrium (DUE); Wardrop
    relative gap convergence criterion; deterministic shortest-path or
    logit auxiliary assignment.  Implemented in
    \texttt{src/ev\_power\_traffic/ctm\_propagation.cpp}; entry point
    \texttt{simulate\_ev\_power\_traffic\_ctm\_due()}; validated by
    \texttt{test\_ev\_power\_traffic\_ctm\_due.cpp} (7~test cases,
    106~assertions).  \textbf{Limitation}: does not perform smart-charging
    dispatch or DC-OPF coupling; station arrivals and EV load synthesis
    remain future work for this path.
  \item[Formulation~C.]
    Formulation~B plus iterative DC-OPF LMP price coordination
    (\textbf{implemented}): the CTM-DUE inner step provides EV loads per
    station per time step; the DC-OPF outer step extracts nodal LMPs and
    updates station prices via a convex combination; the loop repeats until
    price convergence.  Social welfare $W = B_{\mathrm{EV}} - C_{\mathrm{gen}}
    - C_{\mathrm{delay}}$ is tracked at each iteration.
    Entry point: \texttt{simulate\_ev\_power\_traffic\_ctm\_joint()};
    implementation: \texttt{src/ev\_power\_traffic/ctm\_joint\_welfare.cpp};
    validated by \texttt{test\_ev\_power\_traffic\_ctm\_joint.cpp}
    (5~test cases, 43~assertions).
  \item[Formulation~D (\textbf{implemented, validated};~\S\ref{sec:evpt-formulation-d-case}).]
    Route assignment (free-flow arrival steps), optional DC-OPF power
    balance, V2G, and station-capacity constraints are assembled into a
    single LP/QP/MILP/MCP in one solver call.  Supports
    \texttt{SocialWelfareMax}, \texttt{UserBenefitMax}, and
    \texttt{UserEquilibriumMILP} objectives.  Solver certificates
    (primal feasibility, dual bound, MIP gap) are populated for every
    solve.  Entry point: \texttt{solve\_joint\_optimizer()};
    implementation: \texttt{src/ev\_power\_traffic/joint\_optimizer.cpp};
    validated by
    \texttt{test\_ev\_power\_traffic\_joint\_opt\_d.cpp}
    (7~test cases, 55~assertions).
\end{description}

Sections~\ref{sec:evpt-traffic}--\ref{sec:evpt-jsw} describe
Formulation~A in full mathematical detail.
Section~\ref{sec:evpt-ctm-due} documents Formulation~B.
Section~\ref{sec:evpt-formulation-d} gives Formulation~D, the
solver-certified dynamic joint-optimization model.
The numerical case studies
(Sections~\ref{sec:evpt-toy-case}--\ref{sec:evpt-largescale-case})
validate Formulation~A.  Section~\ref{sec:evpt-ctm-due-case} presents
Formulation~B results.  Formulation~C is reported in
Section~\ref{sec:evpt-ctm-joint-case}.
Formulation~D is validated in Section~\ref{sec:evpt-formulation-d-case}.

\begin{remark}[Certificate scope]
  Solver optimality certificates apply only to the LP/MILP objective and
  constraints of Formulation~A
  (Eq.~\eqref{eq:evpt-lp-obj}--\eqref{eq:evpt-lp-gen}).  This
  formulation is globally optimal only for its own surrogate problem:
  free-flow route costs, static road-capacity screening, fixed
  dwell-window charging profiles, and optional aggregate generation
  capacity.  Any BPR travel time, queueing delay, AC power-flow result,
  or welfare value reported \emph{after} the LP solve is an ex-post
  diagnostic unless it is explicitly a decision variable or constraint
  in the mathematical program.  Formulation~B returns a DUE route-flow
  estimate via CTM propagation and MSA; it does not invoke the LP or
  OPF layer.  Formulation~C is a price-coordination fixed-point
  algorithm rather than one integrated mathematical program.  B/C
  convergence is empirically validated by regression tests and is not
  a solver certificate.  When certification is required, use
  Formulation~D and report the optimisation status, primal feasibility,
  best bound, and optimality/MIP gap.
\end{remark}

\subsection{Time Grid, Sets, and Notation}
\label{sec:evpt-sets}
% ------------------------------------------------------------

\subsubsection{Single Time Grid}

The simulation uses a single uniform time grid with \(K\) steps:
\[
  \mathcal{T} = \{0,1,\ldots,K{-}1\},\qquad
  t_k = k\,\Delta t,
\]
where \(\Delta t\) is the step duration in hours (\texttt{options.time\_step\_hr},
default 1~h) and \(K\) is the number of steps
(\texttt{options.num\_steps}, default 24).  There is no separate traffic
time grid.  Formulation~B (Section~\ref{sec:evpt-ctm-due}) internally
refines this grid to a finer CTM time step \(\Delta t_{\mathrm{ctm}}\).
Unless stated otherwise, index \(k\) refers to the simulation grid
\(\mathcal{T}\); within Formulation~B the CTM step index is written
\(\kappa\in\{0,\ldots,T_{\mathrm{ctm}}{-}1\}\).

\subsection{Traffic Flow Model}
\label{sec:evpt-traffic}
% ------------------------------------------------------------

\subsubsection{Link Capacity and Travel Time (BPR Function)}

The per-step vehicle capacity of directed link \(a\in\mathcal{A}\) at
step \(k\) is
\[
  C_{a,k} = c_a\,\Delta t,
\]
where \(c_a\) is the link flow capacity in veh/h
(\texttt{TrafficLink::capacity\_veh\_per\_hr}).

The link travel time is modelled by the Bureau of Public Roads (BPR)
volume--delay function.  Given that \(x_{a,k}\) vehicles use link \(a\)
at step \(k\), the travel time in hours is
\begin{equation}
  t_{a,k}
  \;=\;
  t_a^0
  \left[
    1 + \alpha_a
    \left(
      \frac{x_{a,k}}{C_{a,k}}
    \right)^{\!\beta_a}
  \right],
  \label{eq:evpt-bpr}
\end{equation}
where \(t_a^0\) is the free-flow travel time (\texttt{free\_flow\_time\_hr}),
\(\alpha_a=0.15\) and \(\beta_a=4\) are the BPR calibration parameters
(\texttt{TrafficLink::alpha}, \texttt{TrafficLink::beta}).
When \(C_{a,k}=0\) (blocked link) the travel time is set to \(+\infty\).

\subsubsection{Route Travel Time}

Route \(r\in\mathcal{R}\) is a sequence of directed links
\(r=(a_1,a_2,\ldots,a_L)\).  Its travel time at step \(k\) is
\begin{equation}
  T_{r,k} \;=\; \sum_{a\in r} t_{a,k}.
  \label{eq:evpt-route-tt}
\end{equation}

\subsubsection{Generalized Route Cost}

Route \(r\) serves demand \(d\in\mathcal{D}\) departing at step \(k\).
The generalized cost used by the heuristic assignment modes
(Deterministic Shortest Path, Logit, Capacity-Aware Greedy) is
\begin{equation}
  c_{d,r,k}
  \;=\;
  \mathrm{VOT}\cdot T_{r,k}
  \;+\;
  \omega_s
    \sum_{s\in\mathcal{S}(r)}
      \pi_{s,k}\,e_{r,s}
  \;+\;
  \omega_Q \sum_{s\in\mathcal{S}(r)} W_{s,k_{\mathrm{arr}}(r,k)}
  \;+\;
  \mathrm{toll}_r,
  \label{eq:evpt-gen-cost}
\end{equation}
where \(\mathcal{S}(r)\) is the set of charging stops on route \(r\),
\(e_{r,s}\) is the per-vehicle energy requested at stop \(s\)
(\texttt{requested\_energy\_kwh\_per\_vehicle}), \(W_{s,k}\) is the
estimated waiting time at station \(s\) at step \(k\)
(Section~\ref{sec:evpt-queue}), \(k_{\mathrm{arr}}(r,k)\) is the arrival
step at the stop (rounded from free-flow travel time), and
\(\mathrm{toll}_r\) is any optional route toll
(\texttt{RouteAlternative::toll\_cost}).

When computing the \emph{free-flow} cost for the system-optimal LP
objective (Section~\ref{sec:evpt-solp}), the actual link travel times
are replaced by free-flow values \(t_a^0\), and the queueing term is
dropped.

\subsubsection{Implemented SOC Feasibility Filter}

When a demand specifies an initial battery energy
\(E^{init}_d\ge0\), the route candidate set is filtered before
assignment.  Let \(\epsilon_a\) denote the per-vehicle traction-energy
coefficient of link \(a\) [kWh/(veh\,km)].  Along route
\(r=(a_1,\ldots,a_L)\), the implemented path-energy recursion is
\begin{align}
  E_{d,r,0} &= E^{init}_d, \nonumber\\
  E_{d,r,\ell}
  &=
  E_{d,r,\ell-1} - \epsilon_{a_\ell}L_{a_\ell},
  &&\ell=1,\ldots,L,
  \label{eq:evpt-route-soc} \\
  E^{post}_{d,r}
  &=
  \min\!\left(
    \bar E_d,\;
    E_{d,r,L}
    + \sum_{s\in\mathcal{S}(r)} e_{r,s}
  \right).
  \nonumber
\end{align}
The route is feasible only if the battery stays within the configured
SOC bounds:
\begin{equation}
  \underline E_d
  \le
  E_{d,r,\ell}
  \le
  \bar E_d,
  \qquad
  \ell=0,\ldots,L,
  \qquad
  E^{post}_{d,r}\ge\underline E_d.
  \label{eq:evpt-route-soc-bounds}
\end{equation}
If \(E^{init}_d<0\), or if no link on the route provides
\(\epsilon_a>0\), this filter is disabled for backward compatibility.

% ------------------------------------------------------------
\subsection{Assignment Models}
\label{sec:evpt-assignment-models}
% ------------------------------------------------------------

Four assignment policies are selectable via
\texttt{options.assignment\_model}:

\subsubsection{Deterministic Shortest Path (\texttt{DeterministicShortestPath})}

All \(q_d\) vehicles of demand \(d\) are assigned to the single route
with minimum generalized cost:
\[
  r^* = \arg\min_{r\in\mathcal{R}_d} c_{d,r,k_d}.
\]
No capacity constraint is enforced.

\subsubsection{Logit (\texttt{Logit})}

When road capacity constraints are not enforced, vehicles are split
using the multinomial logit model:
\begin{equation}
  x_{d,r}
  \;=\;
  q_d\,
  \frac{e^{-\theta\,c_{d,r,k_d}}}
       {\sum_{r'\in\mathcal{R}_d} e^{-\theta\,c_{d,r',k_d}}},
  \qquad r\in\mathcal{R}_d.
  \label{eq:evpt-logit}
\end{equation}
Routes with \(c_{d,r,k_d}=+\infty\) receive zero weight.

\subsubsection{Capacity-Aware Greedy (\texttt{CapacityAwareGreedy})}

Routes are sorted by ascending generalized cost.  For each route \(r\)
the algorithm assigns
\[
  x_{d,r}
  \;=\;
  \min\bigl(
    \mathrm{remaining}_d,\;
    \mathrm{road\_res}_{r,k},\;
    \mathrm{sta\_res}_{r,k}
  \bigr),
\]
where \(\mathrm{road\_res}_{r,k}=\min_{a\in r}(C_{a,k}-\mathrm{used}_{a,k})\)
and \(\mathrm{sta\_res}_{r,k}\) is the remaining charging capacity
at each stop.  Used-capacity and reserved-station-power arrays are
updated after each assignment.

\subsubsection{System-Optimal LP / MILP}
\label{sec:evpt-solp}

See Section~\ref{sec:evpt-lp-formulation} for the full formulation.
The continuous LP is solved by the native dual-simplex implementation
(\texttt{engine::solve\_lp\_with\_basis}).  The integer MILP variant
attempts HiGHS first, falling back to the native branch-and-cut solver
(\texttt{engine::solve\_milp\_bc}).

% ------------------------------------------------------------
\subsection{System-Optimal LP Formulation}
\label{sec:evpt-lp-formulation}
% ------------------------------------------------------------

\subsubsection{Assumptions (Formulation~A)}

The following conditions are required for the LP to be well-posed and
its solution to be globally optimal for the system-optimal assignment
problem:

\begin{enumerate}
  \item \textbf{System-optimal, not DUE.}  The LP minimises total
        system cost; it does not model user equilibrium or
        complementarity conditions.
  \item \textbf{Continuous flows.}  Route assignment variables
        \(x_{d,r}\ge0\) are continuous; the MILP variant adds
        integrality constraints.
  \item \textbf{Free-flow costs in objective.}  The cost coefficients
        \(c^{\mathrm{ff}}_{d,r}\) are precomputed from free-flow travel
        times \(t_a^0\); BPR congestion does not appear in the LP
        objective.  Consequently the LP solution may assign more vehicles
        to a route than the greedy congestion-aware heuristic would
        (see Sections~\ref{sec:evpt-toy-case}--\ref{sec:evpt-largescale-case}).
  \item \textbf{Fixed charging profile.}  Station power is a fixed
        linear function of route flows via the dwell-window convolution
        (Eq.~\eqref{eq:evpt-lp-station}); smart-charging flexibility
        is not modeled in the LP itself.
  \item \textbf{No V2G in LP.}  \(P^{EV}_{s,k}\ge0\) holds implicitly
        because \(p^{\mathrm{req}}_{r,s}\ge0\) and \(x_{d,r}\ge0\).  V2G
        discharge is available separately via the smart-charging LP
        (Section~\ref{sec:evpt-sessions}).
  \item \textbf{Precomputed arrival steps.}  Station arrival steps
        \(k_{\mathrm{arr}}\) are derived from free-flow travel times and
        are fixed parameters, not optimisation variables.
  \item \textbf{DC power flow (optional).}  Power-system coupling uses
        linear DC-OPF when enabled; AC nonconvexity is not modeled.
\end{enumerate}

\subsubsection{Decision Variables}

\begin{center}
\begin{tabular}{lll}
\hline\hline
\textbf{Variable} & \textbf{Domain} & \textbf{Meaning} \\
\hline
\(x_{d,r}\ge0\) & veh & vehicles of demand \(d\) on route \(r\) \\
\(u_d\ge0\)     & veh & unserved vehicles for demand \(d\) \\
\hline\hline
\end{tabular}
\end{center}

\subsubsection{Objective}

Minimise total free-flow generalized cost plus unserved-demand penalty:
\begin{equation}
  \min\quad
  \sum_{d\in\mathcal{D}}
  \sum_{r\in\mathcal{R}_d}
    c^{\mathrm{ff}}_{d,r}\,x_{d,r}
  \;+\;
  M^{trip} \sum_{d\in\mathcal{D}} u_d,
  \label{eq:evpt-lp-obj}
\end{equation}
where \(c^{\mathrm{ff}}_{d,r}\) is the free-flow generalized cost
(\(T_{r,k}\) evaluated at \(t^0_a\)) and \(M^{trip}=10^6\) by default.

\subsubsection{Demand Balance}

\begin{align}
  \sum_{r\in\mathcal{R}_d} x_{d,r} + u_d &= q_d,
  &&\forall d\in\mathcal{D}.
  \label{eq:evpt-lp-demand}
\end{align}

\subsubsection{Road Capacity}

If \texttt{enforce\_road\_capacity} is enabled:
\begin{align}
  \sum_{\substack{d\in\mathcal{D},\;r\in\mathcal{R}_d:\\a\in r}}
    x_{d,r}
  &\le C_{a,k_d},
  &&\forall a\in\mathcal{A}.
  \label{eq:evpt-lp-road}
\end{align}
Constraints are grouped by (departure step, link index).

\begin{remark}[Static path-capacity screening]
  The road-capacity rows~\eqref{eq:evpt-lp-road} are static screening
  constraints indexed by demand departure step~$k_d$.  A vehicle on
  route~$r$ is charged against every link $a\in r$ at $k_d$, regardless
  of when it actually arrives at link~$a$.  These rows prevent gross
  over-assignment to a congested corridor but do not propagate link
  occupancy over time and therefore do not model spillback, downstream
  capacity at actual arrival times, or link storage.  Dynamic link
  occupancy is captured only in the CTM module of Formulation~B.
\end{remark}

\subsubsection{Station Charging Capacity}

For each station \(s\) and each step \(k\) in a dwell window:
\begin{align}
  \sum_{\substack{d,\;r\in\mathcal{R}_d:\;s\in\mathcal{S}(r),\\
        k\in[k_{\mathrm{arr}},k_{\mathrm{arr}}+\Delta_s)}}
    p^{\mathrm{req}}_{r,s}\, x_{d,r}
  &\le P^{\max}_s,
  &&\forall s\in\mathcal{S},\;k\in\mathcal{T},
  \label{eq:evpt-lp-station}
\end{align}
where \(p^{\mathrm{req}}_{r,s}=e_{r,s}/(\Delta_s\,\Delta t)\) [kW/veh]
is the required charging power per vehicle and \(\Delta_s\) is the
dwell duration in steps (\texttt{dwell\_steps}).

\subsubsection{Generation Capacity (Optional)}

If \texttt{enforce\_generation\_capacity} is enabled:
\begin{align}
  \sum_{\substack{d,r,s:\;s\in\mathcal{S}(r),\\k\in\text{dwell window}}}
    p^{\mathrm{req}}_{r,s}\, x_{d,r}
  &\le (P^{\mathrm{gen}}_{\max} - P^{\mathrm{base}})\times 1000,
  &&\forall k\in\mathcal{T}.
  \label{eq:evpt-lp-gen}
\end{align}

\begin{remark}[Aggregate generation screen]
  Equation~\eqref{eq:evpt-lp-gen} is a system-wide aggregate power
  adequacy check.  It does not represent bus-level locational pricing,
  branch flow limits, voltage constraints, generator redispatch, or AC
  feasibility.  Full network feasibility requires DC-OPF or AC
  power-flow validation (Section~\ref{sec:evpt-power-coupling}).
\end{remark}

\subsubsection{MILP Variant}

When \texttt{SystemOptimalMILP} is selected and all \(q_d\) are
integers, the variables are declared integer:
\(x_{d,r},\,u_d\in\mathbb{Z}_{\ge0}\).
Non-integer demand triggers an automatic fallback to the LP relaxation.

\subsection{Charging Session Synthesis}
\label{sec:evpt-sessions}
% ------------------------------------------------------------

After route assignment, each route flow \(x_{d,r}>0\) generates one
\texttt{EVChargingSession} per charging stop on route \(r\):

\begin{center}
\begin{tabular}{ll}
\hline\hline
\textbf{Session field} & \textbf{Value} \\
\hline
\texttt{arrival\_step}    & \(k_d + \lceil T_{r,k_d}^{\mathrm{ff}}/\Delta t \rceil\) \\
\texttt{departure\_step}  & \(\min(K,\;k_{\mathrm{arr}} + \Delta_s)\) \\
\texttt{vehicle\_count}   & \(x_{d,r}\) \\
\texttt{energy\_target\_kwh} & \(e_{r,s}\cdot x_{d,r}\) \\
\texttt{max\_charge\_kw}  & \(p^{ch,\max}_{r,s}\cdot x_{d,r}\) \\
\hline\hline
\end{tabular}
\end{center}

\subsubsection{Smart Charging LP}

For each session \(v\) with dwell window
\([k_{\mathrm{arr}},k_{\mathrm{dep}})\), a per-session LP allocates
charging and discharging power:
\begin{align}
  \min\quad & \rho\,\xi_v
  \label{eq:evpt-smart-obj} \\
  \text{s.t.}\quad
  \sum_{k=k_{\mathrm{arr}}}^{k_{\mathrm{dep}}-1}
    \left(
      \eta^{ch}\,p^{ch}_{v,k}
      - \frac{p^{dis}_{v,k}}{\eta^{dis}}
    \right)\Delta t
    + \xi_v
  &\;\ge\; E^{\mathrm{req}}_v,
  \label{eq:evpt-smart-energy} \\
  0 \le p^{ch}_{v,k}  &\le p^{ch,\max}_v,
  \label{eq:evpt-smart-ub-ch} \\
  0 \le p^{dis}_{v,k} &\le p^{dis,\max}_v\cdot\mathbf{1}[\mathrm{V2G}],
  \label{eq:evpt-smart-ub-dis} \\
  \xi_v &\ge 0,
  \label{eq:evpt-smart-slack}
\end{align}
where $E^{\mathrm{req}}_v = e_{r,s}\cdot x_{d,r}$ [kWh] is the
requested delivered energy for session~$v$ (not a final SOC target);
$\eta^{ch}\in(0,1]$ is charging efficiency and $\eta^{dis}\in(0,1]$
is discharging efficiency (both default to the single parameter
\texttt{default\_charging\_efficiency}, default~1.0); slack
$\xi_v\ge0$ represents unserved energy with penalty weight~$\rho$.
With $\eta^{ch}=\eta^{dis}=\eta$ the net battery gain per step is
$\eta\,p^{ch}_{v,k} - p^{dis}_{v,k}/\eta$.  V2G is disabled when
$p^{dis,\max}_v=0$ (\texttt{v2g\_capable = false}).

\begin{remark}[Per-session LP and station-level capacity]
  The per-session LP does not by itself enforce station-level aggregate
  power limits.  In the LP/MILP assignment mode, station feasibility is
  enforced upstream by Eq.~\eqref{eq:evpt-lp-station}.  In
  Deterministic Shortest Path and Logit modes, station capacity is not
  guaranteed; excess requested energy may be reported as unserved.
\end{remark}

The net station power at step \(k\) is
\[
  P^{EV}_{s,k}
  \;=\;
  \sum_{\substack{v:\;s_v=s,\\k\in[k_{\mathrm{arr}},k_{\mathrm{dep}})}}
    (p^{ch}_{v,k} - p^{dis}_{v,k}).
\]

% ------------------------------------------------------------
\subsection{Station Queue and Occupancy Model}
\label{sec:evpt-queue}
% ------------------------------------------------------------

The simulation tracks a discrete-time queue for each station
\(s\in\mathcal{S}\).  Define:
\begin{itemize}
  \item \(\lambda_{s,k}\): vehicles arriving at station \(s\) at step
        \(k\) (from route assignments with matching arrival step),
  \item \(m_{s,k}\): plug-occupancy at step \(k\) --- number of
        vehicles already plugged in (from session schedules),
  \item \(N^{\mathrm{plug}}_s\): number of plugs (\texttt{n\_fast}).
\end{itemize}

\subsubsection{Queue Dynamics}

The number of vehicles that can begin charging at step \(k\) is
\begin{equation}
  u_{s,k}
  \;=\;
  \min\!\left(
    q_{s,k} + \lambda_{s,k},\;
    \max\!\left(0,\; N^{\mathrm{plug}}_s - m_{s,k}\right)
  \right),
  \label{eq:evpt-queue-serve}
\end{equation}
and the queue evolves as
\begin{equation}
  q_{s,k+1}
  \;=\;
  \max\!\left(0,\; q_{s,k} + \lambda_{s,k} - u_{s,k}\right),
  \qquad q_{s,0} = 0.
  \label{eq:evpt-queue-update}
\end{equation}

\subsubsection{Service Completion}

For a fixed dwell duration of \(\Delta_s\) steps, the service
completion rate is
\begin{equation}
  r_{s,k} \;=\; u_{s,k-\Delta_s}, \qquad k\ge\Delta_s;
  \qquad r_{s,k}=0 \text{ for } k<\Delta_s.
  \label{eq:evpt-queue-complete}
\end{equation}
The plug occupancy then evolves as
\begin{equation}
  m_{s,k+1} \;=\; m_{s,k} + u_{s,k} - r_{s,k},
  \qquad m_{s,0}=0.
  \label{eq:evpt-plug-occ}
\end{equation}
In the forward simulation, the session schedule derived from
Section~\ref{sec:evpt-sessions} provides the actual \(m_{s,k}\)
directly; Eq.~\eqref{eq:evpt-plug-occ} is used for prospective
queueing estimates when session schedules are not yet available
(e.g.\ in the first assignment pass).

\subsubsection{Waiting Time Approximation}

\begin{equation}
  W_{s,k}
  \;\approx\;
  \frac{q_{s,k}}{\mu_s}\,\Delta t,
  \qquad
  \mu_s
  \;=\;
  \frac{N^{\mathrm{plug}}_s}{\Delta_s}
  \;\approx\;
  \frac{P^{\max}_s}{p_{\mathrm{veh}}\,\Delta_s},
  \label{eq:evpt-wait}
\end{equation}
where $\mu_s$ [vehicles/step] is the effective service throughput---the
number of vehicles completing service per step when the station is at
full capacity---and $p_{\mathrm{veh}}$ is the per-vehicle charging
power (\texttt{default\_route\_stop\_power\_kw\_per\_vehicle}).
For a one-step dwell ($\Delta_s=1$), $\mu_s = N^{\mathrm{plug}}_s$.
The waiting time $W_{s,k}$ [h] feeds the generalized cost
\eqref{eq:evpt-gen-cost} via \(\omega_Q\).

\subsection{Power-System Coupling}
\label{sec:evpt-power-coupling}
% ------------------------------------------------------------

\subsubsection{Station Load Write-Back}

After smart charging dispatch, \texttt{apply\_ev\_station\_loads}
adds the per-step EV load to the corresponding bus:
\[
  P^d_{b(s),k} \;\mathrel{+}=\; P^{EV}_{s,k}\times10^{-3}\;[\mathrm{MW}].
\]
A negative \(P^{EV}_{s,k}\) (V2G discharge) reduces the bus load.

\subsubsection{Optional Power-Flow Validation}

If \texttt{run\_power\_flow\_validation = true}, the AC power flow is
solved for each step using
\texttt{solve\_power\_flow(step\_system, pf\_options)}.
The generation capacity margin is checked:
\[
  P^{\mathrm{gen}}_{\max}
  \;-\;
  P^{\mathrm{base}}
  \;-\;
  \sum_s P^{EV}_{s,k}\times10^{-3}
  \;\ge\;0.
\]

\subsection{Joint Social Welfare Algorithm}
\label{sec:evpt-jsw}
% ------------------------------------------------------------

\texttt{solve\_joint\_social\_welfare()} in
\texttt{src/ev\_power\_traffic/joint\_social\_welfare.cpp}
implements iterative LMP-price coordination.

\begin{remark}[Coordination heuristic, not a global optimizer]
  The JSW routine is a decentralized fixed-point coordination heuristic;
  it does not solve a single integrated social-welfare maximization
  problem.  Its fixed point, when reached, is a consistency state
  between the traffic LP response to current prices and the DC-OPF LMPs
  under the resulting loads.  Convergence and global welfare optimality
  are not guaranteed for arbitrary networks or loading conditions; the
  algorithm has been validated on the cases in
  Section~\ref{sec:evpt-jsw-case}.
\end{remark}

\subsubsection{Sub-Problems}

\paragraph{Traffic sub-problem.}
Given prices \(\pi^{(i)}\), solve the system-optimal LP
\eqref{eq:evpt-lp-obj}--\eqref{eq:evpt-lp-gen} to obtain
\(x^{(i)},P^{EV,(i)}\).

\paragraph{Power sub-problem.}
For each step \(k\), solve the DC-OPF with EV loads
\(P^{EV,(i)}_{s,k}\) added to their buses.  Let \(\mathcal{G}_i\)
denote generators at bus \(i\):
\[
  \min_{P^g_{g,k}}
  \sum_{g\in\mathcal{G}} \bigl(c_{2,g}(P^g_{g,k})^2 + c_{1,g}P^g_{g,k} + c_{0,g}\bigr)\Delta t
\]
subject to DC power balance at each bus \(i\):
\[
  \sum_{g\in\mathcal{G}_i} P^g_{g,k} - P^d_{i,k}
  \;=\; \sum_j B_{ij}\,\theta_{j,k},
\]
branch flow limits \(-\bar F_\ell \le b_\ell(\theta_{i(\ell),k}-\theta_{j(\ell),k})\le\bar F_\ell\),
and generator bounds \(\underline{P}^g_g\le P^g_{g,k}\le\bar P^g_g\).
Output: dispatch \(P^{g,(i)}_{g,k}\), LMPs \(\lambda^{(i)}_{b,k}\)
[\$/MWh] as dual variables of the power-balance constraints.

\subsubsection{Price Update}

\begin{equation}
  \pi^{(i+1)}_{s,k}
  \;=\;
  \alpha\,\frac{\lambda^{(i)}_{b(s),k}}{1000}
  \;+\;
  (1-\alpha)\,\pi^{(i)}_{s,k}.
  \label{eq:evpt-price-update}
\end{equation}
The factor of 1000 converts \$/MWh to \$/kWh.

\begin{remark}[LMP role in the JSW scheme]
  In the power sub-problem, \(\lambda^{(i)}_{b,k}\) is the dual variable
  of the DC power-balance constraint at bus \(b\), i.e.\ the
  locational marginal price (LMP) [\/MWh]; it reflects the marginal
  increase in generation cost for a 1~MW load increase at bus \(b\).
  In the traffic sub-problem, the same value is used as an
  \emph{exogenous price signal} after unit conversion.  The JSW
  algorithm is a decentralized coordination scheme: the generation cost
  already appears in \(C^{(i)}_{\mathrm{gen}}\) and the station price
  payment is an internal transfer, not a double-count.  In the tested cases, with non-negative generator marginal costs, no
  must-run constraints, and the adopted sign convention, LMPs are
  non-negative.  In general, LMPs can be zero or negative under
  congestion, binding lower-generation limits, renewable spillage, or
  other model features.
\end{remark}

\subsubsection{Convergence Criterion}

\begin{equation}
  \max_{s,k}
  \left|\pi^{(i+1)}_{s,k} - \pi^{(i)}_{s,k}\right|
  \;<\;
  \varepsilon_\pi.
  \label{eq:evpt-conv-crit}
\end{equation}

\subsubsection{Social Welfare Accounting}

\begin{align}
  W^{(i)}
  &= B^{(i)}_{\mathrm{EV}} - C^{(i)}_{\mathrm{gen}} - C^{(i)}_{\mathrm{delay}},
  \label{eq:evpt-welfare} \\
  B^{(i)}_{\mathrm{EV}}
  &= \sum_{d\in\mathcal{D}} \mathrm{WTP}_d\cdot x^{(i)}_d,
  \label{eq:evpt-benefit} \\
  C^{(i)}_{\mathrm{gen}}
  &= \sum_{k\in\mathcal{T}} \text{OPF}_k^{(i)}\;\mathrm{objective},
  \label{eq:evpt-gencost} \\
  C^{(i)}_{\mathrm{delay}}
  &= \mathrm{VOT}\cdot\sum_{d,r} x^{(i)}_{d,r}\cdot T^{(i)}_{r,k_d}.
  \label{eq:evpt-delay}
\end{align}

\subsubsection{Algorithm Summary}

\begin{enumerate}
  \item Initialise \(\pi^{(0)}_{s,k} = \pi_0\) for all \(s,k\).
  \item For \(i=1,\ldots,\texttt{max\_iterations}\):
    \begin{enumerate}
      \item[(a)] Solve traffic LP with \(\pi^{(i-1)}\) to get
                 \(x^{(i)},P^{EV,(i)}\).
      \item[(b)] For each \(k\): solve DC-OPF; extract
                 \(\lambda^{(i)}_{b,k}\).
      \item[(c)] Update \(\pi^{(i)}\) via~\eqref{eq:evpt-price-update}.
      \item[(d)] Compute \(W^{(i)}\), record history.
      \item[(e)] Check~\eqref{eq:evpt-conv-crit}; stop if satisfied.
    \end{enumerate}
\end{enumerate}

% ------------------------------------------------------------
\subsection{Formulation~D: Solver-Certified Dynamic Joint Optimisation}
\label{sec:evpt-formulation-d}
% ------------------------------------------------------------

Formulation~D is the non-heuristic model class for the next
\texttt{ev\_power\_traffic} implementation step.  It replaces
capacity-aware greedy assignment, MSA-DUE, and LMP fixed-point iteration
with a single mathematical program, or with a solver-certified
equilibrium complementarity model.  It is designed to answer the five
requirements that are not fully covered by Formulations~A--C:
\begin{enumerate}
  \item road blockage, capacity derating, incident recovery, and
        spillback-aware road congestion;
  \item EV charging and V2G discharge under battery and station limits;
  \item elastic, time-varying, and departure-time-shifting travel demand;
  \item comparison of user-benefit maximisation and social-welfare
        maximisation;
  \item LP/QP/MILP/MCP solver execution with primal feasibility, dual
        bound, and optimality/MIP-gap certificates.
\end{enumerate}

\subsubsection{Additional Sets and Parameters}

Let \(\mathcal{C}\) be EV user classes and
\(\mathcal{P}_{odc}\) the route set for OD pair \((o,d)\) and class
\(c\).  The simulation horizon is discretised by
\(\mathcal{T}^{D}=\{0,\ldots,K_D-1\}\).  In Formulation~D this grid is
the optimisation grid; it may be chosen equal to the CTM grid or a
coarsened multiple of it.

Road disruptions are represented by exogenous availability and capacity
profiles:
\begin{align}
  \gamma_{a,k} &\in \{0,1\},
      &&\text{availability of road link \(a\) at step \(k\)}, \\
  \phi_{a,k} &\in [0,1],
      &&\text{capacity derating factor during incidents or work zones}.
\end{align}
\(\gamma_{a,k}=0\) models a complete closure; \(0<\phi_{a,k}<1\)
models a partial fault, lane closure, signal failure, or weather-induced
capacity reduction.  The effective road capacity is
\begin{equation}
  \bar q_{a,k}
  =
  \gamma_{a,k}\,\phi_{a,k}\,q_a^{\max}.
  \label{eq:evpt-d-eff-road-cap}
\end{equation}
The same idea applies to charging stations:
\begin{equation}
  \bar P^{ch}_{s,k}=\psi^{ch}_{s,k}P^{ch,\max}_s,
  \qquad
  \bar P^{dis}_{s,k}=\psi^{dis}_{s,k}P^{dis,\max}_s,
  \qquad
  \bar N^{plug}_{s,k}=\psi^{plug}_{s,k}N^{plug}_s,
  \label{eq:evpt-d-station-fault}
\end{equation}
where \(\psi\in[0,1]\) allows charger outages, feeder derating, or
communication failures to be modelled without changing the network
topology.

The time-varying potential travel demand is
\(\bar d_{odc,k}\) [vehicles].  The outside-option utility
\(\Omega_{odc,k}\) is the value retained when a trip is cancelled or
deferred beyond the optimisation horizon.  The gross willingness to pay
or trip benefit is \(B_{odc,k}\) [\$/vehicle].

\subsubsection{Decision Variables}

\begin{center}
\begin{tabular}{lll}
\hline\hline
\textbf{Variable} & \textbf{Domain} & \textbf{Meaning} \\
\hline
\(h_{p,k}\ge0\) & veh & vehicles departing on route \(p\) at step \(k\) \\
\(q_{odc,k}^{ser}\ge0\) & veh & served trips for OD/class/time demand \\
\(q_{odc,k}^{out}\ge0\) & veh & cancelled or horizon-unserved trips \\
\(z_{odc,\tau,k}\ge0\) & veh & trips requested at \(\tau\), departed at \(k\) \\
\(n_{a,m,k}\ge0\) & veh & CTM occupancy of road cell \(m\) on link \(a\) \\
\(y_{a,m,k}\ge0\) & veh/step & CTM inter-cell flow \\
\(e_{v,k}\) & kWh & battery energy of EV/session group \(v\) \\
\(p^{ch}_{v,k},p^{dis}_{v,k}\ge0\) & kW & charging and V2G discharge power \\
\(\delta^{ch}_{v,k},\delta^{dis}_{v,k}\in\{0,1\}\) & -- & optional charge/discharge mode binaries \\
\(P^g_{g,k},\theta_{b,k},f_{\ell,k}\) & MW, rad, MW & DC-OPF generator, angle, and branch-flow variables \\
\(\ell^p_{b,k},\ell^t_{a,k},\ell^e_{v}\ge0\) & load/veh/kWh & slack variables for load, traffic, and energy infeasibility \\
\hline\hline
\end{tabular}
\end{center}

The variables \(z_{odc,\tau,k}\) are needed only when departure-time
choice is enabled.  The variables
\(\delta^{ch}_{v,k},\delta^{dis}_{v,k}\) are needed only when the model
must forbid simultaneous charge and discharge exactly; omitting them
gives a pure LP/QP relaxation that is often exact when round-trip
efficiency is below one and both charge and discharge carry nonnegative
costs.

\subsubsection{Dynamic Travel Demand and Departure-Time Choice}

For inelastic demand, every requested trip must either be served or be
assigned to an explicit outside option:
\begin{align}
  \sum_{\tau\in\mathcal{T}^{D}:\;\tau\ge k}
    z_{odc,k,\tau}
  + q^{out}_{odc,k}
  &= \bar d_{odc,k},
  &&\forall o,d,c,k.
  \label{eq:evpt-d-elastic-demand}
\end{align}
Here \(z_{odc,k,\tau}\) means demand requested at step \(k\) and actually
departing at step \(\tau\).  If departure-time shifting is disabled, set
\(z_{odc,k,\tau}=0\) for \(\tau\ne k\).  The served departure volume at
step \(\tau\) is
\begin{equation}
  q^{ser}_{odc,\tau}
  =
  \sum_{k\le\tau}z_{odc,k,\tau}.
  \label{eq:evpt-d-served-demand}
\end{equation}
Route departure flows satisfy
\begin{equation}
  \sum_{p\in\mathcal{P}_{odc}} h_{p,\tau}
  =
  q^{ser}_{odc,\tau},
  \qquad \forall o,d,c,\tau.
  \label{eq:evpt-d-route-balance}
\end{equation}
Thus travel demand is not forced to be fully satisfied unless the user
sets \(q^{out}_{odc,k}=0\) or assigns an outside-option penalty large
enough to make cancellation economically dominated.  This is important
for emergency road closures, feeder outages, or insufficient charging
capacity, where mandatory service can make the model artificially
infeasible.

\subsubsection{Blockage-Aware CTM Constraints}

For each road link \(a\), cell \(m\), and step \(k\), Formulation~D uses
the CTM as linear inequalities rather than as a forward simulation.  The
state conservation law is
\begin{equation}
  n_{a,m,k+1}
  =
  n_{a,m,k}
  + y_{a,m-1,k}\mathbf{1}[m>0]
  + y^{in}_{a,k}\mathbf{1}[m=0]
  - y_{a,m,k}\mathbf{1}[m<M_a{-}1]
  - y^{out}_{a,k}\mathbf{1}[m=M_a{-}1].
  \label{eq:evpt-d-ctm-conservation}
\end{equation}
The sending and receiving envelopes are written as solver constraints:
\begin{align}
  y_{a,m,k}
  &\le
  \Delta t_D\,\bar q_{a,k},
  &&\forall a,m,k,
  \label{eq:evpt-d-ctm-cap} \\
  y_{a,m,k}
  &\le
  \frac{v^f_a\Delta t_D}{\delta_a}\, n_{a,m,k},
  &&\forall a,m,k,
  \label{eq:evpt-d-ctm-send} \\
  y_{a,m,k}
  &\le
  \frac{w_a\Delta t_D}{\delta_a}
  \left(\gamma_{a,k}N^{jam}_{a}-n_{a,m+1,k}\right),
  &&\forall a,m<M_a{-}1,k,
  \label{eq:evpt-d-ctm-receive} \\
  0\le n_{a,m,k}
  &\le
  \gamma_{a,k}N^{jam}_{a},
  &&\forall a,m,k.
  \label{eq:evpt-d-ctm-storage}
\end{align}
When \(\gamma_{a,k}=0\), Eqs.~\eqref{eq:evpt-d-ctm-cap} and
\eqref{eq:evpt-d-ctm-storage} force zero flow and zero storage on the
closed link.  For an incident that closes only future inflow while
allowing trapped vehicles to drain, replace
\eqref{eq:evpt-d-ctm-storage} by
\(0\le n_{a,m,k}\le N^{jam}_{a}\) and apply \(\gamma_{a,k}\) only to
the sending capacity of entering cells.

Route departure variables inject flow into the first link of each path:
\begin{equation}
  y^{in}_{a,k}
  =
  \sum_{p:\,a=\mathrm{first}(p)}h_{p,k}
  +
  \sum_{b:\,\mathrm{to}(b)=\mathrm{from}(a)} y_{b\to a,k},
  \label{eq:evpt-d-route-injection}
\end{equation}
with node transfer variables \(y_{b\to a,k}\) satisfying merge/diverge
capacity, turning-ratio, and FIFO constraints.  These node constraints
are linear for fixed priorities and fixed route incidence.  If signal
phase decisions or lane-use decisions are optimised, the corresponding
activation variables make the traffic part MILP.

\subsubsection{EV Battery, Charging, and V2G}

Let \(v\) index a homogeneous EV session group generated by a route,
station, and arrival/departure window.  The battery state evolves as
\begin{equation}
  e_{v,k+1}
  =
  e_{v,k}
  - E^{drive}_{v,k}
  + \eta^{ch}_{v}p^{ch}_{v,k}\Delta t_D
  - \frac{p^{dis}_{v,k}}{\eta^{dis}_{v}}\Delta t_D,
  \qquad \forall v,k.
  \label{eq:evpt-d-battery}
\end{equation}
The traction term is
\begin{equation}
  E^{drive}_{v,k}
  =
  \sum_{a\in p(v)}
  \epsilon_{a,c(v)} L_a\,\chi_{v,a,k},
  \label{eq:evpt-drive-energy}
\end{equation}
where \(\epsilon_{a,c}\) is the drive-energy coefficient
[kWh/(veh\,km)] and \(\chi_{v,a,k}\) is the flow or occupancy of group
\(v\) on link \(a\) at step \(k\).  A path-level approximation replaces
\eqref{eq:evpt-drive-energy} by the precomputed route energy
\(\sum_{a\in p}\epsilon_{a,c}L_a\).

Battery limits and terminal service requirements are
\begin{align}
  \underline E_{v,k}
  \le e_{v,k}
  &\le
  \bar E_{v,k},
  &&\forall v,k,
  \label{eq:evpt-d-soc-bounds} \\
  e_{v,k^{dep}_v}
  + \ell^e_v
  &\ge
  E^{target}_v,
  &&\forall v.
  \label{eq:evpt-d-terminal-energy}
\end{align}
Charging and discharge power are restricted to the connection window:
\begin{align}
  0 \le p^{ch}_{v,k}
  &\le
  A_{v,k}\bar p^{ch}_{v},
  &
  0 \le p^{dis}_{v,k}
  &\le
  A_{v,k}\bar p^{dis}_{v},
  &&\forall v,k,
  \label{eq:evpt-d-session-power}
\end{align}
where \(A_{v,k}=1\) if the session is plugged in at step \(k\) and zero
otherwise.  Exact no-simultaneous-charge/discharge logic is
\begin{align}
  p^{ch}_{v,k} &\le A_{v,k}\bar p^{ch}_{v}\delta^{ch}_{v,k}, \\
  p^{dis}_{v,k} &\le A_{v,k}\bar p^{dis}_{v}\delta^{dis}_{v,k}, \\
  \delta^{ch}_{v,k}+\delta^{dis}_{v,k} &\le 1,
  \qquad \delta^{ch}_{v,k},\delta^{dis}_{v,k}\in\{0,1\}.
  \label{eq:evpt-d-charge-discharge-mode}
\end{align}
Equations~\eqref{eq:evpt-d-battery}--\eqref{eq:evpt-d-charge-discharge-mode}
allow both normal charging and reverse discharge.  Negative net station
power is therefore a decision outcome, not a post-processing convention.

Station aggregate limits are
\begin{align}
  \sum_{v:s(v)=s}p^{ch}_{v,k}
  &\le
  \bar P^{ch}_{s,k},
  &&\forall s,k,
  \label{eq:evpt-d-station-ch-limit} \\
  \sum_{v:s(v)=s}p^{dis}_{v,k}
  &\le
  \bar P^{dis}_{s,k},
  &&\forall s,k,
  \label{eq:evpt-d-station-dis-limit} \\
  \sum_{v:s(v)=s}A_{v,k}
  &\le
  \bar N^{plug}_{s,k},
  &&\forall s,k.
  \label{eq:evpt-d-plug-limit}
\end{align}
If plug assignment is optimised rather than fixed from arrival windows,
\(A_{v,k}\) becomes binary and the station submodel is MILP.

\subsubsection{Power-Network Constraints}

For a DC-OPF coupling, station net power is
\begin{equation}
  P^{EV}_{s,k}
  =
  10^{-3}\sum_{v:s(v)=s}
  \left(p^{ch}_{v,k}-p^{dis}_{v,k}\right)
  \quad [\mathrm{MW}].
  \label{eq:evpt-d-station-net-power}
\end{equation}
The nodal power balance is
\begin{equation}
  \sum_{g\in\mathcal{G}_b} P^g_{g,k}
  - P^d_{b,k}
  - \sum_{s:b(s)=b}P^{EV}_{s,k}
  + \ell^p_{b,k}
  =
  \sum_{\ell\in\delta(b)} \sigma_{b\ell} f_{\ell,k},
  \qquad \forall b,k.
  \label{eq:evpt-d-power-balance}
\end{equation}
Branch and generator limits are
\begin{align}
  f_{\ell,k}
  &=
  b_{\ell}\left(\theta_{i(\ell),k}-\theta_{j(\ell),k}\right),
  &&\forall \ell,k,
  \label{eq:evpt-d-dc-flow} \\
  -\bar F_{\ell}
  \le f_{\ell,k}
  &\le
  \bar F_{\ell},
  &&\forall \ell,k,
  \label{eq:evpt-d-branch-limit} \\
  \underline P^g_g
  \le P^g_{g,k}
  &\le
  \bar P^g_g,
  &&\forall g,k.
  \label{eq:evpt-d-gen-limit}
\end{align}
If voltage magnitude or radial distribution losses must be represented,
Eqs.~\eqref{eq:evpt-d-power-balance}--\eqref{eq:evpt-d-gen-limit}
can be replaced by LinDistFlow constraints.  Full AC constraints make
the model nonlinear; IPOPT can solve the continuous NLP relaxation, but
integer route, plug, or charge/discharge decisions still require an
MINLP strategy or an outer branch-and-bound solver.

\subsubsection{Objective 1: User-Benefit Maximisation}
\label{sec:evpt-d-user-benefit}

User-benefit maximisation represents a platform or behavioural model
that prioritises EV users' private utility.  A linear form is
\begin{align}
  \max\quad
  U^{user}
  &=
  \sum_{o,d,c,k} B_{odc,k}q^{ser}_{odc,k}
  - \mathrm{VOT}_c
    \sum_{p,k} h_{p,k}T_{p,k}
  - \sum_{v,k}\pi_{s(v),k}
    \left(p^{ch}_{v,k}-p^{dis}_{v,k}\right)\Delta t_D
  \nonumber\\
  &\quad
  - \sum_{o,d,c,k} \Omega_{odc,k}q^{out}_{odc,k}
  - \sum_{v,k} c^{deg}_v p^{dis}_{v,k}\Delta t_D
  - M_e\sum_v \ell^e_v.
  \label{eq:evpt-d-user-objective}
\end{align}
Here \(T_{p,k}\) may be either a CTM-derived linear travel-time proxy,
the sum of link occupancies
\(\sum_{a,m,k}n_{a,m,k}\Delta t_D\), or a convex piecewise-linear delay
function.  The private electricity payment is included because it
affects the user's route, station, charging, and V2G decisions.  In a
pure user-benefit analysis, generation cost is not subtracted unless it
is passed through to users as price.

\subsubsection{Objective 2: Social-Welfare Maximisation}
\label{sec:evpt-d-social-welfare}

Social welfare counts real resource costs and treats electricity
payments as internal transfers:
\begin{align}
  \max\quad
  W
  &=
  \sum_{o,d,c,k} B_{odc,k}q^{ser}_{odc,k}
  - \mathrm{VOT}_c\sum_{a,m,k} n_{a,m,k}\Delta t_D
  - \sum_{g,k} C_g(P^g_{g,k})\Delta t_D
  \nonumber\\
  &\quad
  - \sum_{v,k} c^{deg}_v p^{dis}_{v,k}\Delta t_D
  - M_{out}\sum_{o,d,c,k}q^{out}_{odc,k}
  - M_p\sum_{b,k}\ell^p_{b,k}
  - M_e\sum_v\ell^e_v
  - M_t\sum_{a,k}\ell^t_{a,k}.
  \label{eq:evpt-d-social-objective}
\end{align}
If generator costs \(C_g(\cdot)\) are linear or piecewise linear, the
model is LP/MILP.  If \(C_g(P)=c_{2,g}P^2+c_{1,g}P+c_{0,g}\) with
\(c_{2,g}\ge0\), the continuous relaxation is convex QP; with mode,
plug, or signal binaries it becomes MIQP.

\begin{remark}[User optimum vs. social optimum]
  The user-benefit objective~\eqref{eq:evpt-d-user-objective} can prefer
  cheap private routes and stations even when they create congestion,
  grid congestion, or high generation cost elsewhere.  The social-welfare
  objective~\eqref{eq:evpt-d-social-objective} internalises these costs.
  Comparing the two solves gives the efficiency loss of selfish or
  price-responsive behaviour under the same physical constraints:
  \[
    \mathrm{PoA}^{D}
    =
    \frac{W^{SO}}{W^{UE\;or\;UB}},
  \]
  when both welfare values are evaluated with
  Eq.~\eqref{eq:evpt-d-social-objective}.  This comparison is meaningful
  because the numerator and denominator use the same CTM and power model.
\end{remark}

\subsubsection{Solver-Certified User Equilibrium}

If the study requires Dynamic User Equilibrium rather than centralised
user-benefit maximisation, route choice is written as variational
inequality or complementarity conditions.  Let
\(G_{p,k}(x,p^{ch},p^{dis})\) be the generalised private cost of route
\(p\) for the relevant OD/class/departure time, and let
\(\mu_{odc,k}\) be the minimum perceived cost.  Wardrop equilibrium is
\begin{align}
  G_{p,k}-\mu_{odc,k} &\ge 0,
  &&\forall p\in\mathcal{P}_{odc},k,
  \label{eq:evpt-d-ue-cost} \\
  h_{p,k} &\ge 0,
  &&\forall p,k,
  \label{eq:evpt-d-ue-flow} \\
  h_{p,k}\left(G_{p,k}-\mu_{odc,k}\right) &=0,
  &&\forall p\in\mathcal{P}_{odc},k.
  \label{eq:evpt-d-ue-comp}
\end{align}
For separable monotone link costs, the UE can also be solved by the
convex Beckmann program.  For the full EV-power-traffic model with
station capacity, V2G, and grid coupling, the complementarity system is
assembled as MCP or converted to MILP with big-\(M\) and binary
activation:
\begin{align}
  G_{p,k}-\mu_{odc,k}
  &\le M^{UE}_{p,k}(1-b_{p,k}),\\
  h_{p,k}
  &\le M^{flow}_{p,k}b_{p,k},\\
  b_{p,k}&\in\{0,1\}.
  \label{eq:evpt-d-ue-milp}
\end{align}
This is solver-certified in the sense that the MCP residual, or the MILP
feasibility and MIP gap, is reported directly by the solver.  It is not
an MSA iteration and does not rely on empirical convergence of
successive averages.

\subsubsection{Problem Class and Solver Selection}

The exact solver class is determined by the selected modelling features:
\begin{center}
\begin{tabular}{lll}
\hline\hline
\textbf{Features} & \textbf{Problem class} & \textbf{Recommended solver path} \\
\hline
Linear CTM, linear costs, fixed plug windows & LP & HiGHS or native LP \\
Quadratic generation cost, no binaries & convex QP & QP-capable backend \\
Integer route/plug/mode/signal decisions & MILP/MIQP & HiGHS/SCIP/Gurobi/native B\&C \\
Wardrop complementarity, no binaries & MCP/QP-KKT & MCP solver or KKT system \\
AC power flow only, continuous variables & NLP & IPOPT local solve \\
AC power flow plus integer decisions & MINLP & outer MIP/MINLP solver; IPOPT only for NLP relaxations \\
\hline\hline
\end{tabular}
\end{center}

IPOPT is therefore not the default solver for Formulation~D.  It is
appropriate only when the assembled problem is a continuous nonlinear
program, such as an AC-OPF refinement with fixed route and charging-mode
decisions.  IPOPT does not provide a global MIP gap for integer route,
station, plug, V2G-mode, or signal decisions.  For the requested
non-heuristic execution, the primary implementation should first assemble
LP/QP/MILP/MIQP models; IPOPT can be added later as an AC feasibility
polishing or continuous-NLP validation layer.

\subsubsection{Solver Algorithm}
\label{sec:evpt-d-solver-algorithm}

The solver-certified execution pipeline is:
\begin{enumerate}
  \item \textbf{Build the time-expanded network.}  Expand road links into
        CTM cells over \(\mathcal{T}^{D}\), attach route incidence, station
        arrival windows, charging buses, demand profiles
        \(\bar d_{odc,k}\), and disruption profiles
        \(\gamma_{a,k},\phi_{a,k},\psi_{s,k}\).
  \item \textbf{Choose the behavioural mode.}  Select
        \texttt{UserBenefitMax}, \texttt{SocialWelfareMax}, or
        \texttt{UserEquilibriumMCP}.  The first two are optimisation
        objectives; the last adds complementarity or big-\(M\) equilibrium
        constraints.
  \item \textbf{Assemble one model.}  Add
        Eqs.~\eqref{eq:evpt-d-elastic-demand}--\eqref{eq:evpt-d-gen-limit}
        and one of
        Eqs.~\eqref{eq:evpt-d-user-objective},
        \eqref{eq:evpt-d-social-objective}, or
        \eqref{eq:evpt-d-ue-cost}--\eqref{eq:evpt-d-ue-milp}.
        Use piecewise-linear epigraph variables for nonlinear delay or
        generator-cost terms when a pure LP/MILP is desired.
  \item \textbf{Solve with a mathematical-programming backend.}  Run the
        LP/QP/MILP/MIQP/MCP solver with configured feasibility tolerance,
        time limit, node limit, and MIP-gap target.  No route-flow update,
        price smoothing, greedy repair, or MSA step is part of the
        certified solve.
  \item \textbf{Validate the certificate.}  Accept the result only if the
        solver status is feasible/optimal according to the selected
        tolerance.  Record primal maximum violation, dual bound or best
        bound, incumbent objective, relative MIP gap, node count, and
        solve time.  For LP/QP, require a valid optimal basis or KKT
        residual; for MCP, require complementarity residual below the
        tolerance.
  \item \textbf{Decode and cross-check.}  Convert \(h,n,y,e,p^{ch},p^{dis}\)
        into route assignments, CTM link states, station loads, SOC
        trajectories, V2G injections, and power-system dispatch.  Optionally
        run the existing AC power-flow validation as an ex-post check.
\end{enumerate}

\begin{remark}[Heuristic methods retained only as baselines]
  \texttt{CapacityAwareGreedy}, MSA-DUE, greedy smart charging, and
  LMP-price smoothing remain useful for fast simulation, warm starts, and
  regression baselines.  They should not be used to claim optimality,
  equilibrium, or social-welfare maximisation when Formulation~D is the
  selected model.  Certified numerical results must come from the solver
  certificate of the assembled LP/QP/MILP/MIQP/MCP.
\end{remark}

\subsection{Formulation~B: CTM Propagation and Dynamic User Equilibrium}
\label{sec:evpt-ctm-due}
% ------------------------------------------------------------

\subsubsection{Cell Transmission Model}

Following Daganzo (1994), each directed link $a\in\mathcal{A}$ is
discretised into $M_a$ cells of equal length
$\delta_a = L_a / M_a$ [km],
with a dedicated CTM time step $\Delta t_{\mathrm{ctm}}$ satisfying the
CFL stability condition:
\begin{equation}
  \Delta t_{\mathrm{ctm}} \;\le\; \frac{\delta_a}{v^f_a},
  \qquad\forall a\in\mathcal{A}.
  \label{eq:evpt-cfl}
\end{equation}
The number of cells is computed as
\begin{equation}
  M_a = \max\!\left(1,\;\left\lfloor\frac{L_a}{v^f_a\,\Delta t_{\mathrm{ctm}}}\right\rfloor\right),
  \label{eq:evpt-m-cells}
\end{equation}
or overridden by \texttt{CTMOptions::n\_cells\_per\_link} when positive.
When \texttt{dt\_ctm\_hr = 0} the implementation auto-selects
$\Delta t_{\mathrm{ctm}} = 0.9\cdot\min_a(\delta_a/v^f_a)$, which
satisfies CFL for all links.  If a user-specified
$\Delta t_{\mathrm{ctm}}$ is so large that $L_a/(v^f_a\Delta t_{\mathrm{ctm}})<1$
for some link, then $M_a$ is clamped to~1 and the CFL
condition~\eqref{eq:evpt-cfl} cannot be restored by cell splitting;
the implementation proceeds with an approximate single-cell propagation
for that link.

\subsubsection{Triangular Fundamental Diagram}

The triangular fundamental diagram is parametrised by free-flow speed
$v^f_a$ [km/h], backward wave speed $w_a$ [km/h], and capacity
$q^{\max}_a$ [veh/h].  Jam density and jam occupancy per cell are
\begin{equation}
  k^{\mathrm{jam}}_a
  \;=\;
  \frac{q^{\max}_a(v^f_a+w_a)}{v^f_a\,w_a},
  \qquad
  N^{\mathrm{jam}}_a = k^{\mathrm{jam}}_a\,\delta_a.
  \label{eq:evpt-kjam}
\end{equation}
When \texttt{TrafficLink::jam\_vehicles} is zero, the backward wave
speed is inferred from $k^{\mathrm{jam}} = 2\,q^{\max}/v^f$ (symmetric
triangular FD); otherwise
$w_a = q^{\max}_a / (k^{\mathrm{jam}}_a - q^{\max}_a/v^f_a)$.

\subsubsection{Sending and Receiving Functions}

At step $k$ the vehicle flow that cell $m$ can \emph{send} downstream
and the flow that cell $m{+}1$ can \emph{receive} are:
\begin{align}
  S_{a,m,k}
  &= \Delta t_{\mathrm{ctm}}\cdot
     \min\!\left(\frac{n_{a,m,k}\,v^f_a}{\delta_a},\;q^{\max}_a\right),
  \label{eq:evpt-send} \\
  R_{a,m,k}
  &= \Delta t_{\mathrm{ctm}}\cdot
     \min\!\left(q^{\max}_a,\;
     \frac{w_a\,\max(0,\,N^{\mathrm{jam}}_a - n_{a,m,k})}{\delta_a}\right).
  \label{eq:evpt-recv}
\end{align}

\subsubsection{Cell Update}

The inter-cell flow is
\begin{equation}
  y_{a,m,k} = \min\bigl(S_{a,m,k},\;R_{a,m+1,k}\bigr),
  \qquad m=0,\ldots,M_a{-}2,
  \label{eq:evpt-intercell}
\end{equation}
and the cell occupancy evolves as
\begin{equation}
  n_{a,m,k+1}
  \;=\;
  n_{a,m,k}
  + y_{a,m-1,k}\cdot\mathbf{1}[m>0]
  - y_{a,m,k}\cdot\mathbf{1}[m<M_a{-}1],
  \qquad n_{a,m,0}=0.
  \label{eq:evpt-cell-update}
\end{equation}
The indicator functions subsume three distinct boundary cases:
\begin{align*}
  m=0:\quad & n_{a,0,k+1} = n_{a,0,k} + y^{in}_{a,k} - y_{a,0,k}, \\
  0<m<M_a{-}1:\quad & n_{a,m,k+1} = n_{a,m,k} + y_{a,m-1,k} - y_{a,m,k}, \\
  m=M_a{-}1:\quad & n_{a,M_a{-}1,k+1} = n_{a,M_a{-}1,k} + y_{a,M_a{-}2,k} - y^{out}_{a,k},
\end{align*}
where $y^{in}_{a,k}$ is the external inflow from origin demand injection
or upstream node, and $y^{out}_{a,k}$ is the exit flow to the downstream
node.

\subsubsection{Commodity-Specific Cell Occupancy}

With \texttt{route\_specific\_cells = true} (default), each cell stores
per-route occupancy $n^r_{a,m,k}$ alongside the aggregate $n_{a,m,k}$.
At diverge nodes, vehicles are distributed to downstream links according
to binary turning indicators
$\theta^r_{a\to v\to b}\in\{0,1\}$ extracted from route topologies.
The per-route shares are renormalised to sum to $n_{a,m,k}$ after each
update step, maintaining aggregate consistency.  This renormalisation
is an engineering correction: per-route occupancy conservation is
\emph{approximate} rather than an exact independent commodity
conservation law.  Exact commodity conservation would require
per-route sending/receiving functions and independent per-route cell
updates, which are not implemented.

\subsubsection{Node Model}

At node $v$ with incoming link $a$ and outgoing links $b$, the exit
flow from the last cell of $a$ is allocated proportionally:
\begin{align}
  f_{a\to b,k}
  &= S_{a,M_a{-}1,k}\cdot\frac{\mathrm{demand}_{a\to b}}{\mathrm{total\_demand}_a}\cdot\sigma_k,
  \label{eq:evpt-node-model}
\end{align}
where $\mathrm{demand}_{a\to b}=\sum_r n^r_{a,M_a{-}1,k}\,\theta^r_{a\to v\to b}$
and $\sigma_k$ is a scale factor that ensures no outgoing link receives
more than its receiving capacity.

\begin{remark}[Proportional node rule]
  Equation~\eqref{eq:evpt-node-model} is a proportional demand-scaling
  rule.  It preserves route-direction information and respects
  downstream receiving capacities but is not a full priority-based CTM
  node model; it does not represent merge priority, FIFO diverge
  behaviour, lane groups, or signal timing.
\end{remark}

\subsubsection{Experienced Link Travel Time}

The experienced travel time on link $a$ at step $k$ is estimated via
Little's law:
\begin{equation}
  T^{\mathrm{CTM}}_{a,k}
  \;=\;
  \begin{cases}
    \dfrac{N_{a,k}\,\Delta t_{\mathrm{ctm}}}{\mathrm{exit}_{a,k}}
    & \text{if } \mathrm{exit}_{a,k}>0, \\
    L_a / v^f_a & \text{otherwise,}
  \end{cases}
  \label{eq:evpt-ctm-tt}
\end{equation}
where $N_{a,k}=\sum_m n_{a,m,k}$ and $\mathrm{exit}_{a,k}$ is the exit
flow from the last cell.  Route experienced travel time is the sum over
links: $T^{\mathrm{CTM}}_{r,k}=\sum_{a\in r} T^{\mathrm{CTM}}_{a,k}$.

\begin{remark}[Instantaneous approximation]
  Equation~\eqref{eq:evpt-ctm-tt} is an instantaneous Little's-law
  estimate, not the exact experienced travel time for vehicles entering
  at step~$\kappa$.  The exact experienced time requires tracking
  cumulative entry and exit counts and inverting the exit condition.  The
  instantaneous approximation is adequate for near-equilibrium flows but
  may be less accurate under severe transient congestion.
\end{remark}

\subsubsection{Method of Successive Averages (MSA) for DUE}

Given experienced travel times from the CTM forward pass, the
auxiliary assignment is an all-or-nothing (AoN) assignment to the
cheapest route per OD pair, or a logit split when
\texttt{DUEOptions::logit\_theta}>0.

The \textbf{generalized route cost} used for route comparison combines
the CTM travel time with a normalised charging-cost term:
\begin{equation}
  g_r(k)
  \;=\;
  T^{\mathrm{CTM}}_{r,k}
  +
  \frac{\omega_E}{\mathrm{VOT}}
  \sum_{s\in\mathcal{S}_r}
  \pi_{s,k}\,E^{\mathrm{req}}_{r,s},
  \label{eq:evpt-aux-gen-cost}
\end{equation}
where $\omega_E$ is \texttt{station\_energy\_cost\_weight},
VOT is the value-of-time [\$/h], $\pi_{s,k}$~[\$/kWh] is the
station price at step~$k$, and $E^{\mathrm{req}}_{r,s}$~[kWh/veh] is
the energy requested at stop~$s$ on route~$r$.
With $\pi_{s,k} = 0$ (or $\omega_E = 0$) the generalized cost reduces
to travel time, recovering the standard CTM-DUE.  Station prices set by
Formulation~C's outer loop are propagated through this equation, creating
a behavioural coupling between electricity prices and route choice.

The MSA update is
\begin{equation}
  x^{(i+1)}
  \;=\;
  \bigl(1 - s_i\bigr)\,x^{(i)}
  + s_i\,x^{\mathrm{aux}},
  \qquad
  s_i
  =
  \begin{cases}
    1/i & \texttt{msa\_fixed\_step}=0, \\
    \texttt{msa\_fixed\_step} & \text{otherwise.}
  \end{cases}
  \label{eq:evpt-msa}
\end{equation}

\subsubsection{Wardrop Relative Gap}

The stopping criterion uses the relative Wardrop gap:
\begin{equation}
  \varepsilon^{\mathrm{gap}}
  \;=\;
  \frac{\mathrm{TSTT} - \mathrm{MSTT}}{\mathrm{MSTT}}
  \;\ge\;0,
  \label{eq:evpt-ward-gap}
\end{equation}
where $\mathrm{TSTT}=\sum_{d,r} x_{d,r}\,T^{\mathrm{CTM}}_{r,k_d}$ is
the total system travel time and
$\mathrm{MSTT}=\sum_d q_d\cdot\min_r T^{\mathrm{CTM}}_{r,k_d}$ is the
minimum achievable travel time if all vehicles used their cheapest
route.  Convergence is declared when
$\varepsilon^{\mathrm{gap}}<\texttt{DUEOptions::convergence\_tol}$
(default $10^{-3}$).

\begin{remark}[MSA convergence]
  The MSA procedure is an iterative heuristic for approaching a DUE.
  Convergence of MSA to DUE is not guaranteed for arbitrary dynamic
  loading conditions, approximate travel-time estimates, or logit
  auxiliary assignments.  The relative gap serves as an empirical
  diagnostic; convergence has been validated by the regression tests but
  may not hold for all network configurations.
\end{remark}

\subsubsection{CTM Time Step vs.~Simulation Time Step}

The CTM time step $\Delta t_{\mathrm{ctm}}$ is generally finer than the
simulation time step $\Delta t$.  The CTM horizon contains
\begin{equation}
  T_{\mathrm{ctm}}
  \;=\;
  T_{\mathrm{sim}}\cdot R,
  \qquad
  R = \operatorname{round}(\Delta t / \Delta t_{\mathrm{ctm}})
  \label{eq:evpt-ctm-steps}
\end{equation}
steps.  A demand with simulation departure step $k_d$ is injected at
CTM step $k_d\cdot R$.  The \texttt{auxiliary\_assignment} and
\texttt{wardrop\_relative\_gap} functions index \texttt{route\_flow} at
$k_d\cdot R$ accordingly.

\subsubsection{Formulation~B+ Extensions: Session Synthesis, Dispatch, and PoA}
\label{sec:evpt-ctm-due-extensions}

Following DUE convergence, \texttt{simulate\_ev\_power\_traffic\_ctm\_due()}
performs three additional steps that bring Formulation~B to parity with
Formulation~A for charging analysis (hereafter \emph{Formulation~B+}):

\paragraph{Session synthesis.}  Each (demand~$d$, route~$r$, stop~$s$)
triple with positive DUE flow $x_{d,r} > 0$ yields one
\texttt{EVChargingSession}.  The station arrival step is computed from the
\emph{CTM-derived} experienced travel time $T^{\mathrm{CTM}}_{r,k_d}$
rather than free-flow time, making it congestion-aware:
\begin{equation}
  k^{\mathrm{arr}}_{d,r}
  \;=\;
  k_d + \left\lceil T^{\mathrm{CTM}}_{r,k_d\cdot R}\,/\,\Delta t \right\rceil.
  \label{eq:evpt-ctm-session-arr}
\end{equation}

\paragraph{Smart-charging dispatch.}  Each session is dispatched with the
same greedy heuristic as Formulation~A
(Eqs.~\eqref{eq:evpt-smart-obj}--\eqref{eq:evpt-smart-slack}): charge at
maximum feasible power within the dwell window until $E^{\mathrm{req}}$ is
met; discharge via V2G only when the station price exceeds
$\pi^{\mathrm{high}}$.  Station capacity headroom is shared across sessions
at the same station and step.

\paragraph{Station queue model.}  The sessions' arrival schedule drives the
queue dynamics of Eqs.~\eqref{eq:evpt-queue-serve}--\eqref{eq:evpt-wait},
yielding $q_{s,k}$, $m_{s,k}$, and $W_{s,k}$ over the simulation horizon.

\paragraph{Price-of-anarchy benchmark.}  When
\texttt{DUEOptions::compute\_system\_optimal\_benchmark = true}, the DUE
total system travel time (TSTT)
\begin{equation}
  \mathrm{TSTT}^{\mathrm{DUE}}
  \;=\;
  \sum_{d}\sum_{r\in\mathcal{R}_d}
  x_{d,r}\,T^{\mathrm{CTM}}_{r,k_d\cdot R}
  \label{eq:evpt-ctm-tstt-due}
\end{equation}
is compared with the Formulation~A system-optimal LP TSTT
$\mathrm{TSTT}^{\mathrm{SO}}$ to yield the approximate price of anarchy:
\begin{equation}
  \mathrm{PoA}
  \;\approx\;
  \frac{\mathrm{TSTT}^{\mathrm{DUE}}}{\mathrm{TSTT}^{\mathrm{SO}}}.
  \label{eq:evpt-poa}
\end{equation}
The two TSTTs use different underlying traffic models (CTM vs.\ BPR), so
the ratio is approximate; it serves as an upper-bound indicator of DUE
inefficiency.

\paragraph{SOC feasibility filter.}  During each MSA auxiliary assignment,
routes for which the accumulated drive energy exceeds the vehicle's initial
state-of-charge are excluded from consideration
(Eq.~\eqref{eq:evpt-route-soc-bounds}).  This prevents DUE from routing
energy-deficient vehicles along long detours.

\begin{remark}[DC-OPF coupling in Formulation~C]
  DC-OPF coupling is intentionally \emph{not} embedded inside
  \texttt{simulate\_ev\_power\_traffic\_ctm\_due()} (Formulation~B).
  It is the responsibility of the outer coordination loop in
  \texttt{simulate\_ev\_power\_traffic\_ctm\_joint()} (Formulation~C,
  Section~\ref{sec:evpt-ctm-joint-case}) to inject EV loads into the
  power system, solve the DC-OPF, extract LMPs, and update station prices
  before re-invoking the CTM-DUE inner step.
\end{remark}

\subsubsection{Expected Optimal Solution}

Station~101 caps route~1 at $\bar P_{101}/p_{\mathrm{veh}} =
40/20 = 2$~vehicles.  The remaining 2 vehicles take route~2.
At step~1 each station sees 2~vehicles charging at 20~kW/veh
($=0.04$~MW per station).

\paragraph{Without OPF ($C_{\mathrm{gen}}=0$):}
\begin{align}
  B_{\mathrm{EV}} &= 4 \times 50 = \$200, \\
  C_{\mathrm{delay}} &= 1\,(2{\times}0.5 + 2{\times}1.0) = \$3, \\
  W^* &= \$197.
\end{align}

\paragraph{With DC-OPF coupling:}
The joint LP adds generator dispatch $P^g_{g,k}$, bus angles
$\theta_{b,k}$, and branch flows $f_{\ell,k}$ as decision variables
and enforces
\[
  P^g_{g,k} - P^{D}_{b,k} - P^{\mathrm{EV}}_{b,k}
  = \sum_{\ell} B_\ell (\theta_{i_\ell,k}-\theta_{j_\ell,k}), \quad \forall b,k.
\]
G1 (bus~1, $c_1{=}10$) is cheapest and serves
$P^g_{1,1} \approx 0.08$~MW:
\begin{align}
  C_{\mathrm{gen}} &= 10 \times 0.08 \times 1\,\mathrm{h} = \$0.80, \\
  W^* &= 200 - 3 - 0.80 = \$196.20.
\end{align}

\begin{remark}[Formulation~D vs.\ Formulation~C comparison]
  Formulation~D produces a solver certificate in a single LP/MILP call
  (NativeDualSimplex, $\approx$2\,ms for the 2-bus case with 45 variables
  and 25 constraints).  Formulation~C requires 20+ iterative DC-OPF
  plus CTM-DUE calls to converge.  The LP welfare bound $W_D$ dominates
  $W_C$ by construction because every feasible solution of the iterative
  scheme is also feasible for the joint LP.
\end{remark}
