\section{Current C++ Architecture}
\label{sec:architecture}

This section describes the repository as it exists in the current C++ module.
The library target is \texttt{hacdcpf}, configured from the top-level
\texttt{CMakeLists.txt} as a C++20 static library.  The build links against
\texttt{mipsolvers::mipsolvers}; that dependency supplies the shared engine
types, solver adapters, and numerical backends used by the OPF and RPO code.

\subsection{Source Layout}

\begin{longtable}{L{0.22\linewidth}L{0.58\linewidth}}
\toprule
Directory & Current role \\
\midrule
\endhead
\texttt{include/hacdcpf/model} & Public data structures for AC, DC, converter, switching, three-phase, and result models. \\
\texttt{include/hacdcpf/api} & High-level public API facade in \texttt{hacdcpf.hpp}. \\
\texttt{include/hacdcpf/power\_flow} and \texttt{src/power\_flow} & Hybrid Newton PF, DC PF, FDPF, adaptive/islanded/distributed-slack variants, HELM, continuation, Jacobian assembly, and PF utilities. \\
\texttt{include/hacdcpf/optimal\_power\_flow} and \texttt{src/optimal\_power\_flow} & AC OPF routing, parity formulation, parity IPM, DC OPF, and reactive-power optimization. \\
\texttt{include/hacdcpf/power\_models} and \texttt{src/power\_models} & Builder-style models for AC OPF, AC/DC OPF, DC OPF, LinDistFlow, and SCUC experiments. \\
\texttt{include/hacdcpf/io} and \texttt{src/io} & MATPOWER/JSON/JPC case I/O, optional Excel workbook I/O, optional OpenDSS bridge, and case builders. \\
\texttt{include/hacdcpf/analysis} and \texttt{src/analysis} & Declared analysis families; several source files are currently stubs and are called out in Section~\ref{sec:scope-boundary}. \\
\texttt{include/hacdcpf/engine} & Compatibility/forwarding headers into \texttt{mipsolvers::engine}, plus the hacdcpf Newton PF class declaration.  There is no \texttt{src/engine} directory in this repository. \\
\bottomrule
\end{longtable}

\subsection{Top-Level Public API}

The facade header \texttt{include/hacdcpf/api/hacdcpf.hpp} currently exposes:
\begin{itemize}
  \item PF: \texttt{solve\_power\_flow}, \texttt{solve\_dc\_power\_flow},
  \texttt{solve\_power\_flow\_adaptive}, \texttt{solve\_power\_flow\_islanded},
  \texttt{solve\_power\_flow\_distributed\_slack},
  \texttt{solve\_power\_flow\_distributed\_slack\_full},
  \texttt{solve\_power\_flow\_fdpf}, and \texttt{solve\_ac\_dc\_power\_flow};
  \item persistent PF handles: \texttt{create\_solver\_handle},
  \texttt{reset\_solver\_handle}, \texttt{solve\_handle},
  \texttt{solve\_dc\_handle}, and \texttt{destroy\_solver\_handle};
  \item OPF: \texttt{solve\_ac\_opf}, \texttt{solve\_dc\_opf}, and
  \texttt{solve\_rpo};
  \item analysis facade: \texttt{run\_distribution\_resilience\_assessment},
  which is currently backed by a stub implementation.
\end{itemize}

Lower-level namespaces expose additional solver objects and helper entry
points.  The power-flow namespace includes \texttt{solve\_hybrid},
\texttt{solve\_hybrid\_adaptive}, \texttt{solve\_ac}, \texttt{solve\_dc},
\texttt{FDPFSolver}, \texttt{AdaptiveSolver}, \texttt{DistributedSlackSolver},
\texttt{HelmSolver}, \texttt{CpfSolver}, \texttt{HomotopyContinuationSolver},
and the header-only \texttt{solve\_three\_phase} wrapper.

\toprule
CMake option & Default & Current effect \\
\midrule
\endhead

\texttt{HACDCPF\_ENABLE\_EXCEL} & \texttt{OFF} & Adds \texttt{src/io/excel\_io.cpp}; otherwise \texttt{HACDCPF\_NO\_EXCEL} is defined and the public Excel functions throw. \\
