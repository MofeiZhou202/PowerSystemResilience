# 电力系统最优潮流模块的定制化加速技术方案
## ——基于 Native IPM 现有架构的 OPF 结构利用、质量收敛与 CPU 高性能路线

> **定位与前提**：本方案基于用户上传的两份文档（《Native IPM 结构化性能提升与等价基准 2026-08-06》《Native LP 内点法理论设计与验证路线》）与公开文献（MadNLP/LiftedKKT/HyKKT/ExaSGD 系列、HSL MA27/MA57、Tinney 稀疏三角分解等）。**硬件约束为仅 CPU**；OPF 为极坐标电压、大规模（≥1 万母线）、单次与多场景负载并存。**当前代码的已知短板**（case30/118/300 主轨迹末端 stationarity 收敛困难、Ipopt 在 OPF 上仍更快）直接决定下列优先级。

---

## 1 模块计算解剖：OPF 的 CPU 时间到底花在哪

Native IPM 每次内点迭代的工作可分解为五块，OPF 的定制化必须按此逐项画像、逐项压榨：

| 阶段 | 计算内容 | 典型占比（OPF, CPU） | 定制化杠杆 |
|---|---|---|---|
| **AD/导数** | ∇f, J_g=∇g, W=∇²_xx L | 15–35%（极坐标二阶项多） | **解析导数 + 稀疏模式缓存** |
| **KKT 组装** | 填充 H+Σ_x, J_h^T(M/S)J_h 等 | 5–15% | 结构预分配、SIMD 组装 |
| **符号分解** | AMD/ND 排序 + 符号 LU | 首迭代 5–10%，后续≈0 | **一次化 + 多场景复用** |
| **数值分解** | LDLᵀ (LBLᵀ) | **30–50%（大头）** | 排序、超节点、并行、精度 |
| **三角回代** | 前代/回代 (+精化) | 15–30% | 回代并行、精化门控 |

> **证据**：Native IPM 文档已确认 400-bus 探针中 LDLᵀ 后端接通使 factor 从 54 次错误重试降为 6 次、solve 从 22 次降为 16 次，热运行 212 ms → 25.7–32.7 ms。但同文档也承认 Ipopt 在该模型上仅需 1 次迭代（15.4–17.5 ms）而 Native 需 7 次——**说明当前 Native 的差距主要在"迭代质量"而非"线性代数速度"**。这是定制化的第一性判断。

**极坐标 OPF 的特殊性**：潮流约束含 $v_i v_j (G_{ij}\cos\theta_{ij}+B_{ij}\sin\theta_{ij})$ 型双线性-三角复合项，其 Hessian 非零元密集于 4×4 节点块；每个母线的功率平衡方程耦合其全部电气邻域，使 $J_g$ 的每行非零元 $\approx 2(\text{度数}+1)$。这决定了：(i) 解析导数的稀疏模式**随迭代不变**，可一次分析永久复用；(ii) KKT 矩阵的填入主要由高连通度枢纽节点诱发，排序质量对分解成本有数量级影响。

## 2 定制化层一：导数与 KKT 组装的结构压榨（P0，必须做）

### 2.1 解析导数 + 稀疏模式一次化

**做法**：放弃通用 AD，为极坐标潮流方程手写解析梯度/雅可比/拉格朗日 Hessian。把每条线路、每个母线、每台发电机的导数写成**模板函数**（约 15 种计算模式，与 ExaModels.jl 的 SIMD 抽象同构），输入为（节点索引, 线路参数, 当前电压），输出为（稠密小向量/小矩阵）。

**结构利用**：
- 潮流雅可比的稀疏模式 $=$ 电网邻接图的自环增广，**与迭代无关**。在初始化时对 $J_g$ 做一次模式分析（记录每个非零元的来源元件与符号），此后每次迭代只做**数值填充**；
- 拉格朗日 Hessian $W=\nabla^2 f-\sum y_i\nabla^2 g_i$ 的模式 $=J_g$ 模式的二跳闭包，同样一次化；
- 用 `std::vector<int>` 建立"非零元 $\to$ 模板贡献"的 scatter map，组装时按模板批量发射。

**收益量级**：解析导数相对通用 AD 通常 **3–10 倍**；模式缓存消除重复的符号分析（大规模下可观）。这与 Native IPM 文档中"normal-equation scatter map"的设计一致，应推广到 NLP 路径。

### 2.2 OPF 特有的缩放与初始化

**缩放**：极坐标 OPF 中电压幅值 $\sim1$ p.u.、相角 $\sim0.1$ rad、功率 $\sim10^2$ MW，数量级悬殊导致 $W$ 对角元差异大、加剧病态。采用**约束目标缩放**（Ruiz 已用于 LP；NLP 需对约束雅可比与 Hessian 做对角缩放 $D_r A D_c$），目标为使 $\|A\|_\infty\approx1$ 且 $\mathrm{diag}(W)$ 动态范围压缩。注意缩放必须**不改变原空间审计定义**（与 Native LP 的 P2a 契约一致）。

**初始化**：以**热启动点**（上一断面潮流解 / 平坦启动 $v=1,\theta=0$）作为初值，使初始点近似可行，IPM 迭代数可降 30–50%。Native 的 Hybrid AC/DC 桥接已证明"构造一次的 NLPModel 直接交给 NativeIPMAdapter"可行，应把潮流解作为默认初值注入。

## 3 定制化层二：KKT 求解的 OPF 结构选择（P1，核心）

这是**"利用电力系统结构特征"的主战场**。Native IPM 已有 `NewtonFormulation::Auto`（condensed vs augmented 按 symbolic flops 与 nnz(L) 决策），但对 OPF 需做三项定制。

### 3.1 排序算法的电网适配

OPF 的 KKT 矩阵具有**小世界图特性**（少量高连通枢纽诱发大量填入）。默认 AMD 排序对电网矩阵往往不是最优：

- **推荐**：嵌套剖分（METIS/ParMETIS）或 AMD 与 ND 的**符号分解 A/B**（Auto 已有此机制，应把排序算法也纳入候选集）；
- **定制**：对母线按**电气距离/电压等级**分层，强制分区节点最后消去（类似 Tinney 方案 2/3 的思想），可降低填入 20–40%；
- **证据**：文献实测同矩阵不同求解器的因子非零元可差数倍，直接造成分解时间差异。

### 3.2 Condensed 的 OPF 特化：LiftedKKT 式松弛 + 固定主元重分解

Native 的 condensed 路径 $K_c=H+J_h^T(M/S)J_h$ 仍含 $J_g$（等式）块而不定。对 OPF 可做 **LiftedKKT 式改造**：

$$
g(x)=0\;\Rightarrow\;g(x)-s=0,\quad -\tau\le s\le\tau\;(\tau=\varepsilon_{tol}\approx10^{-4})
$$

松弛后等式被"抬升"为界约束，KKT 可完全凝缩到原始空间：

$$
M_{cond}=W+\Sigma_x+A^T\Sigma_s A\;\in\;\mathbb{R}^{n\times n},\quad \textbf{对称正定}
$$

由 Sylvester 惯性律，凡满足下降性的正则化都使 $M_{cond}\succ0$，故可用**无主元 Cholesky 或固定主元序列重分解**——**符号分解一次，整个 IPM 过程只做数值分解**。这对"多场景/滚动窗口"负载是决定性的：不同负荷/拓扑场景共享同一稀疏模式与排序，符号成本被彻底摊销。

**OPF 适配的关键细节**：
- 电网 $A$ 低度、$W$ 带状，$A^T\Sigma_s A$ 仍高度稀疏（二跳闭包），不会像通用 NLP 那样稠密化——这是凝缩法与 OPF"天作之合"的结构原因；
- **必须保留 Richardson 迭代精化**（作用于增广系统），以赎回凝缩的平方级病态（Native 已有后向误差门控机制，直接复用）；
- 精度上限约 $10^{-4}$，对在线 OPF/安全校核足够；若需 $10^{-8}$ 紧容差则切回 augmented LDLᵀ。

### 3.3 并行化：超节点与多线程 LDLᵀ

大规模 OPF 的 LDLᵀ 应利用**超节点（supernodal）结构**：把消去树中结构相似的列聚合为稠密块，以 Level-3 BLAS 并行。Native 已接 PARDISO/MUMPS，应：
- 在 symbolic 阶段导出消去树/超节点大小分布，诊断并行粒度；
- 对高连通枢纽节点形成的"大超节点"做**任务级并行**（PARDISO 的 `iparm[24]` 或 MUMPS 的树并行）；
- 三角回代按消去树分层并行（前代自叶向根、回代自根向叶），这对多场景重复求解是稳定收益。

## 4 定制化层三：主轨迹收敛质量（P2，当前最痛）

Native 文档明确：case30/118/300 的失败模式是"主轨迹末端 stationarity 残差停滞"，crossover 被残差证书门控掉。**这不是线性代数问题，而是 IPM 主轨迹的算法质量问题**，需按 Native LP 文档的分阶段方法系统修复。

### 4.1 等式双对角的 Wächter–Biegler $\delta_C$ stripe

Native NLP 已用"等式双对角 stripe 避免秩亏零模态交给 threshold pivot 隐式扰动"。OPF 的潮流等式在近电压崩溃点雅可比趋于秩亏，应把该机制**参数化暴露**并在 OPF 探针上 A/B：stripe 宽度（如 $10^{-8}$–$10^{-4}$）与惯性目标 $(n, m_{eq}+m_{ineq}, 0)$ 的匹配度，是 stationarity 停滞的常见根因。

### 4.2 末端 active-set crossover 的 OPF 特化

Native 已有"证书型 crossover"：严格互补下用 $\sqrt\mu$ 分离活跃候选、投影到等式补空间、符号门控。OPF 的改进点：
- **活跃集先验**：线路热稳定上限、发电机出力上限的活跃与否，可由**当前潮流越限状态**给出强先验，缩小候选集；
- **避免 case30 的超定行集**（144×132）：候选行先在等式行空间做**数值秩筛选**（QR 或 SVD 容差 $10^{-10}$），只保留独立约束，再解 active KKT；
- **触发条件**：仅在 primal/dual 已通过、唯余 complementarity 失败时触发（Native 已有此门控，保持）。

### 4.3 滤波线搜索与恢复相的 OPF 调参

极坐标 OPF 的强非线性使裸牛顿步常不可行。Ipopt 在 OPF 上"1 次迭代即收敛"的现象（Native 文档记录）提示：其滤波器 + 二阶校正 + 看门狗的组合在近解邻域极为高效。Native 应：
- 在 NLP 路径补全**二阶校正（SOC）**：当全步导致可行性恶化时，解一个修正 RHS 的 KKT（复用分解）恢复可行性；
- **看门狗（watchdog）**：允许非单调残差但限制连续恶化步数；
- 恢复相采用 **Levenberg–Marquardt 可行性恢复**（min $\|g(x)\|$），Native LP 的 P2a 审计契约要求恢复后仍在原空间验证。

## 5 定制化层四：多场景与热启动（P3，负载适配）

"单次 + 多场景"并存的负载要求把**符号分解、排序、甚至数值分解**从单例成本转为**跨场景摊销**：

| 负载形态 | 复用内容 | 机制 |
|---|---|---|
| 滚动窗口 OPF（同拓扑） | 符号分解 + 排序 + 导数模式 | 缓存 `symbolic_L`，仅重做数值分解 |
| N-1 安全校核（同基态） | 上述 + 基态 KKT 因子 | 基态因子作预条件/初值，事故态 Newton–Krylov |
| 多负荷断面（同网络） | 符号分解 + 排序 | 批处理接口：一次 symbolic, N 次 refactor |
| 拓扑变化（检修/故障） | 部分复用 | 增量符号更新（分块 BTF 重排） |

Native LP 文档的"cached/node 路径"与"重复节点热启动"（P5）是现成框架，应扩展到 NLP-OPF：**首节点完整求解，后续节点以基态解 + 缓存符号分解热启动**，这是滚动调度与在线安全分析的性能倍增器。

**工程检查清单**（对应 Native 审核锚点风格）：
1. `OPFModel` 是否输出导数稀疏模式缓存与 scatter map？
2. `NewtonFormulation::Auto` 是否记录两种候选的 symbolic flops/nnz(L) 并支持排序算法 A/B？
3. Condensed 路径是否通过 reduced-space certificate 证明 $J_g$ 满行秩后再用对称 LDLᵀ？
4. 每次分解是否记录路径、正则化、Newton 初始/最终相对残差、精化次数？
5. 多场景接口是否区分首节点/后续节点，并单独报告 prepare/首节点/后续节点分位数？
6. 所有"成功"是否以**原空间 primal/dual/complementarity 审计**为准（不因缩放/松弛放宽）？

## 7 风险与边界

- **凝缩的病态风险**：$\kappa(M_{cond})\sim O(1/\mu^2)$，必须配合精化；对需要 $10^{-8}$ 的紧容差场景应保留 augmented LDLᵀ 回退；
- **解析导数的维护成本**：15 种模板需与模型变更同步，建议以单元测试锁定每种模板的梯度/雅可比数值微分一致性；
- **排序 A/B 的翻转风险**：Auto 决策必须只依赖符号分解 flops/nnz(L)，禁止按案例名硬编码（Native 审计合同）；
- **多场景缓存的失效**：拓扑变化超阈值时缓存的符号分解可能次优，需模式哈希校验 + 失效重建；
- **当前性能定位**：Native 文档已诚实记录"不能宣称 Native 全面领先 Ipopt"，本方案的目标是**在 OPF 特定负载上建立可复现的、结构驱动的优势**，而非通用 NLP 超越。

## 8 与文献路线的对应关系

本方案把 GPU 文献（MadNLP/LiftedKKT/HyKKT/ExaSGD）的方法论**平移到 CPU 语境**：

| GPU 文献机制 | CPU 平移 | 差异 |
|---|---|---|
| 凝缩 SPD → cuDSS Cholesky | 凝缩 SPD → PARDISO/MUMPS 固定主元 LDLᵀ | 无主元/重分解复用价值相同 |
| SIMD AD（ExaModels） | 解析模板导数 + 模式缓存 | CPU 上收益相对较小但确定 |
| 批处理稠密（ExaTron） | 多场景符号缓存 + 共享因子 | CPU 无 warp 级批处理，以缓存替代 |
| 两阶段分解（HiOp） | 滚动窗口热启动 + 事故态 Krylov | 分解思想相同，硬件适配不同 |
| 结构化病态 + 精化 | 直接复用 | 理论完全通用 |

**核心结论**：OPF 定制化的本质不是"换更快的求解器"，而是**把电网的图结构、潮流方程的模板重复性、负载的多场景同构性，转化为导数求值、符号分解、KKT 分解、热启动四个环节的确定性加速**。Native IPM 现有的"结构画像—惯性证书—后向误差门控"架构是正确底座，需补齐的是 OPF 专用的导数模板、凝缩路径的固定主元重分解、以及主轨迹末端的 SOC/crossover 修复。
